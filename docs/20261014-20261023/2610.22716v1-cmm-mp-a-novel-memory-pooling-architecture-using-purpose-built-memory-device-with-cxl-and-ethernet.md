## 摘要
CXL内存模块—内存池化（CMM-MP）提出了一种新颖的内存池化架构，以满足新兴内存密集型工作负载的独特需求。该业界首创的专用内存池化设备，融合了计算快速互联（CXL）的优势以及以太网在可扩展性和成本方面的优势。多个CMM-MP设备协同工作，可提供灵活、可组合且解耦的内存扩展方案。CMM-MP无需修改GPU/CPU应用即可支持数百TB级内存容量。内存池以大容量逻辑聚合内存形式对外呈现，所有内存池发现、组合及后端网络数据通路任务均由设备完全卸载处理。CMM-MP同时支持内存池化与内存共享两种使用模式，可提供2.7微秒的应用延迟和最高达23 GB/s的内存吞吐量。我们的评估表明，CMM-MP在延迟与吞吐量方面显著优于基于RDMA的解决方案。此外，我们还利用CMM-MP评估了Valkey+YCSB与DiskANN等真实应用场景。

## Abstract
CXL Memory Module - Memory Pooling (CMM-MP) introduces a novel memory pooling architecture to meet the unique requirements of emerging memory-intensive workloads. This industry-first, purpose-built memory-pooling device combines the benefits of Compute Express Link (CXL) with the scalability and cost advantages of Ethernet. Multiple CMM-MP devices together provide a flexible, composable, and disaggregated memory expansion solution. The CMM-MP enables 100s of TB capacity for GPU/CPU applications without modifications. The memory pool is exposed as a large-capacity logical aggregate memory, with all pool discovery, composition, and backend network datapath tasks fully offloaded to the device. CMM-MP supports both memory pooling and sharing usage modes. It provides an application latency of 2.7 us and up to 23 GB/s of memory throughput. Our evaluations demonstrate that CMM-MP significantly outperforms RDMA-based solutions in latency and throughput. We also evaluated real-world use cases of Valkey+YCSB and DiskANN using CMM-MP.

## 1. 核心问题与整体含义（研究动机和背景）

- **内存墙加剧**：现代数据中心中，大语言模型（LLM）、图计算、机器学习等内存密集型负载对容量（百TB级）、弹性扩展性与成本效益提出空前需求，而传统服务器受限于物理空间、功耗、散热及NUMA拓扑，难以独立扩展内存。
- **现有方案瓶颈明显**：
  - **RDMA方案**：需侵入式软件修改（显式远程调用）、高上下文切换开销、缺乏原生load/store语义，难以透明支持现有应用；
  - **纯CXL方案**（如CXL交换机/MLD/Multi-Headed Device）：受限于机架级部署、高硬件成本、物理距离短（~3m）、可扩展性差；
  - **混合方案**（如CXL+RDMA）：仍继承RDMA软件栈复杂性，无法实现真正“零修改”透明池化；
  - **其他尝试**（UPI/Ethernet直连、CXL-over-Ethernet）：或不可扩展、或仅支持点对点访问，不提供**多主机共享的统一逻辑内存池视图**。
- **核心目标**：构建一种**无需应用修改、低成本、高可扩展、低延迟、支持多主机并发访问的内存池化基础设施**，推动内存解耦从理论走向实用。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：提出业界首款专用硬件设备 **CMM-MP（CXL Memory Module – Memory Pooling）**，通过**CXL前端 + 以太网后端**的异构协同架构，在保持标准CXL Type 3内存语义的同时，利用成熟、高带宽、低成本的200G以太网构建大规模内存池底座。
- **关键技术创新**：
  - **全硬件卸载的池管理**：所有池发现、地址映射、数据路由、可靠性保障均由设备内FPGA/ARM固件完成，完全不依赖主机OS/驱动。
  - **两级地址翻译机制**：
    - **Host Address (HA) → Normalized Host Address (NHA)**：由BIOS/UEFI将整个池容量映射至系统内存空间，`NHA = HA − HDM_Base`（公式1），实现多主机一致逻辑视图；
    - **NHA → Target Device ID + Device Pool Offset**：通过**Pool Address Map Table (PAMT)** 查表（4K项，粒度可配至64GB），定位数据所在CMM-MP设备及本地偏移（公式2），支持最大256TB池容量。
  - **智能请求路由**：CXL子系统解析请求后，经PAMT查表，若目标Device ID为本机则本地DDR访问；否则交由以太网子系统转发至远端设备。
  - **高可靠以太网传输层**：
    - 使用自定义Transport Packet（含Seq Num、RIFT索引、Opcode等），实现端到端丢包检测、重传、去重、乱序处理；
    - 基于RIFT（Request-In-Flight Table）维护未完成请求上下文，确保响应正确归属；
    - 支持控制面（ARM固件）与数据面（CXL子系统）共用以太网，但通过Ethertype区分。
  - **双模式支持**：
    - **Pooling Mode**：池内存段可独占分配给单个或多个主机；
    - **Sharing Mode**：同一内存段允许多主机并发访问，设备保证原子性（非顺序一致性），上层软件负责缓存一致性（如通过显式同步）。

## 6. 主要结论与发现

- CMM-MP实现了**2.7 μs端到端应用延迟**与**23 GB/s峰值吞吐**，显著优于同平台RDMA方案（RDMA小包延迟~3.17μs，大块吞吐相近但小包差约2×）；
- 在Valkey/YCSB中，**MP-L性能几乎等同于本地内存**（吞吐差距<5%，延迟差距<20%），**MP-R虽有下降但仍远超RDMA**（YCSB吞吐降幅<30%，RDMA未给出同等对比）；
- 在DiskANN中，**MP-L紧贴内存基线，MP-R仍比SSD快约3倍**，证明其在AI向量检索场景中具备极高实用价值；
- 整个内存池（288GB）对主机呈现为**单一、连续、可NUMA感知的逻辑内存空间**，应用无需任何修改即可使用；
- 系统通过**全硬件卸载**（发现、映射、路由、重传）实现高稳定性（24h GSAT无错）与低主机开销。

## 7. 优点

- **首创性与实用性统一**：业界首个将CXL语义与以太网底座深度融合的商用级内存池化设备，兼具标准兼容性与工程落地性；
- **极致透明性**：完全保留CXL Type 3、devdax/fsdax接口，应用“零改造”接入，极大降低迁移门槛；
- **成本与扩展性双赢**：复用成熟200G以太网（非专用CXL交换机），支持跨机架部署，天然支持数百TB级池扩容；
- **软硬协同设计精巧**：
  - PAMT分级映射兼顾灵活性（粒度可配）与效率（4K LUT查表）；
  - RIFT+SeqNum机制在标准以太网上实现了媲美RDMA的可靠传输；
  - ARM+FPGA异构控制面确保功能完备性与实时性。

## 8. 不足与局限

- **应用场景覆盖有限**：实验集中于CPU主导的键值库与向量检索，**缺乏GPU Direct Memory Access（GDMA）或CUDA Unified Memory下的真实AI训练/推理评测**，未验证GPU访存路径（如PCIe/CXL Fabric到GPU的延迟叠加）；
- **一致性模型弱**：Sharing Mode仅保证原子性，不保证顺序一致性，要求上层软件自行处理缓存一致性（如通过锁或消息同步），增加了开发复杂度；
- **网络依赖性强**：性能高度依赖以太网交换机质量（文中使用高端200G交换机），在普通商用交换机或拥塞网络下，延迟与可靠性可能显著劣化；
- **未探索动态资源调度**：当前为静态PAMT配置，未来工作提及“动态分配”，但本文未实现或评测动态重分片、负载均衡、故障迁移等高级管理能力；
- **安全与隔离性未讨论**：未涉及多租户场景下的内存访问隔离、加密、故障域隔离等关键云基础设施要求。
