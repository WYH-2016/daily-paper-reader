## 摘要
部署深度神经网络（DNN）推理任务成本高昂，但单个任务通常难以同时占满GPU的计算单元与内存带宽。通过在同一GPU上共置多个任务实现GPU共享，虽可提升资源利用率，却会引发任务间的相互干扰。现有系统通常采用二元化的计算-内存规则、独立的缩放曲线或模型级预测器来估计此类干扰。然而，这些方法对干扰的理解较为有限：它们基本未探究共置算子的软硬件特性，也无法提供既可解释又准确的延迟 slowdown 预测。本文在流式多处理器（SM）分区机制下开展算子级干扰研究，并借助硬件性能计数器将干扰溯源至共享内存通路的竞争；在此路径上，任一任务的延迟 slowdown 由其共置算子双方共同决定。基于上述发现，我们提出PairSight——一种硬件感知的干扰预测器，它学习共置任务硬件行为间的交互模式，并可在共置前预测各任务的执行延迟。在包括大语言模型（LLM）在内的六种DNN模型上，PairSight在GPU共享场景下的延迟预测平均误差仅为4.3%，显著优于计算-内存强度规则的19.0%；且仅需少量样本即可泛化至未见过的模型与输入。

## Abstract
Serving DNN inference is costly, yet a single task seldom saturates both the compute units and the memory bandwidth of a GPU. GPU sharing raises utilization by co-locating several tasks on one GPU, at the cost of interference among them. Existing systems estimate this interference with binary compute-memory rules, standalone scaling curves, or model-level predictors. However, these estimates rest on a limited understanding of interference. They leave the software and hardware properties of co-located operators largely unexplored and give no slowdown prediction that is both interpretable and accurate. We conduct an operator-level study of interference under SM partitioning and use hardware counters to trace it to contention on the shared memory path, where the slowdown depends jointly on both co-located operators. Based on these findings, we propose PairSight, a hardware-aware interference predictor that learns how the hardware behaviors of co-located tasks interact and predicts the latency of each task before co-location. On six DNN models including LLMs, PairSight predicts latency under sharing with 4.3% mean error, against 19.0% for a compute-memory intensity rule, and adapts to unseen models and inputs with a few samples.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：在 GPU 多租户推理场景中，多个 DNN 任务共置（co-location）于同一 GPU 时，因共享底层硬件资源（尤其是 L2 缓存与 DRAM 通道）而产生**算子级性能干扰（interference）**，导致关键任务（如低延迟高优先级 HP 任务）超时风险上升；现有预测方法无法准确、可解释地量化这种干扰。
- **研究动机**：
  - 现有方法（如 Orion/Usher 的“计算-内存强度互补性规则”、Abacus 等模型级黑盒预测器）仅依赖粗粒度指标（如 operator intensity），忽略**算子对（pairwise）间的硬件行为耦合**；
  - 干扰本质并非单个算子属性，而是两个共置算子在共享内存路径上的**联合争用（joint contention）**，但该机制长期缺乏实证刻画；
  - 调度器需在**共置前**精准预测 latency slowdown（δ），以保障 SLA，而当前方法误差大（>19%）、不可泛化、缺乏硬件依据。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：将 GPU 共置干扰建模为**两个算子在共享 L2/DRAM 路径上的协同竞争行为**，其 slowdown δ 取决于：
  - 目标算子的**未隐藏内存延迟**（由 long-scoreboard / LG-throttle / MIO-throttle stalls 衡量）；
  - 共运行算子（co-runner）施加的**共享路径排队延迟 Q<sub>shared</sub>**（由 DRAM traffic rate 驱动）；
  - 二者交互非线性，需联合建模。

- **关键技术细节**：
  - **硬件感知特征提取**：对每个算子单独运行时，使用 `Nsight Compute` 采集 7 类关键硬件计数器：
    - standalone duration（Dur）；
    - DRAM 总字节数（DRAM）；
    - 3 类 memory-stall：long-scoreboard（LScore）、LG-throttle、MIO-throttle；
    - （可选）L2 throughput/hit rate（用于消融验证）；
  - **Segment-level 输入表示**：将 HP/LP 任务的连续算子序列切分为 ≤16-operator 的 segment，每个算子编码为 token（含 Dur + 4 memory counters + presence flag），保留算子序与角色区分（target vs. co-runner）；
  - **预测模型 PairSight**：
    - 采用**双 XGBoost 回归器**（分别预测 HP 和 LP slowdown），输入为两段算子的 token 序列 + SM 分配（p, q）+ 各自 standalone latency；
    - 模型学习 log δ，自动捕获“compute-bound 算子对 co-runner 不敏感”与“memory-bound 算子高度敏感”的分叉逻辑；
  - **扩展机制**：
    - **Window composition**：对 >16-operator 的长 segment，按顺序切分为窗口，逐窗口预测并累加（公式 (4)），未覆盖窗口直接加 standalone latency；
    - **Few-shot adaptation**：对新模型/新 batch size，仅需新增 ~100 组 co-execution 样本（每组 <0.2s），在 CPU 上微调模型（≤5s/次）。

## 6. 主要结论与发现

- **干扰本质**：GPU 共置干扰主要源于**共享 L2/DRAM 路径的竞争**，而非 SM 计算单元；其 slowdown δ 是**目标算子（未隐藏延迟）与 co-runner（DRAM traffic）的联合函数**，具有方向性、算子特异性、co-runner 依赖性；
- **预测性能**：PairSight 在 HP 侧达 **4.3% MAPE**，显著优于 intensity rule（19.0%）、Abacus（9.2%）、Linear（12.2%）；
- **泛化能力**：
  - 对 Llama 模型冷启动误差 30.2% → few-shot（k=100）后降至 **13.5%**；
  - 支持任意长度 segment（via window composition），96-operator 场景误差仅 **5.5%**；
- **可解释性**：特征源自硬件计数器，模型决策可追溯至具体 stall 类型与 traffic 量，摆脱黑盒依赖。

## 7. 优点

- **首创算子级联合建模**：首个将干扰显式建模为“算子对硬件行为交互”的方法，突破 intensity-centric 范式；
- **硬件原生、轻量部署**：仅需一次 Nsight profiling（离线）+ CPU 训练/推理，零 GPU 开销，适合生产调度器嵌入；
- **强泛化与快速适配**：few-shot adaptation + window composition 实现跨模型、跨 batch、跨长度无缝迁移；
- **实证驱动设计**：全部关键设计（特征选择、token 结构、XGBoost 架构）均经硬件 counter correlation（Fig. 2）与消融（Fig. 4）严格验证；
- **面向落地优化**：预测延迟仅 5.3μs，满足实时调度需求；支持 asymmetric co-execution 场景。

## 8. 不足与局限

- **硬件依赖性**：特征（如 LG-throttle）与模型（XGBoost）针对 NVIDIA GPU（A100/A10）设计，未验证在 AMD CDNA 或 Intel Arc 上的可迁移性；
- **SM 分区假设限制**：方法基于 **SM partitioning（libsmctrl）**，不适用于 MIG（已隔离 L2/DRAM）或时间片轮转（time-slicing）等共享模式；
- **算子边界依赖**：需精确识别 DNN 中每个 kernel 的 operator 边界（依赖框架 profile 工具），对动态图/自定义 kernel 支持未验证；
- **长尾干扰未覆盖**：实验聚焦主流模型，未测试极端稀疏算子（如 MoE top-k）、显存溢出（OOM）或 PCIe 带宽瓶颈等边界 case；
- **冷启动成本**：虽 few-shot，但初始 profiling 仍需在目标 GPU 上运行全部算子（对超大模型如 Llama-3B 可能耗时数分钟）。
