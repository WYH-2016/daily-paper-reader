## 摘要
NVIDIA的Grace Hopper（GH200）超级芯片代表了新一代异构计算架构，它通过高带宽、缓存一致的互连技术，将一颗72核Arm架构CPU与一颗Hopper GPU紧密集成于单一封装模块内。该设计消除了传统PCIe总线在CPU-GPU数据传输中的瓶颈，构建了一个统一内存域，其容量可扩展至生成式人工智能（AI）与高性能计算（HPC）工作负载所要求的规模。该架构还引入了硬件辅助的页迁移机制：系统依据访问计数器动态地将频繁访问的内存页从主机CPU内存提升（promote）至GPU DRAM中，以提升内存局部性。本文研究这一新兴架构在页迁移支持方面面临的新侧信道与隐秘信道攻击的安全风险。我们分析了访问计数器驱动的页迁移机制，覆盖硬件层面的实现以及统一虚拟内存（UVM）驱动程序的中断处理流水线，并识别出两类侧信道漏洞：一类源于访问计数器的共享结构，另一类源于驱动程序对迁移中断的响应行为。进一步研究表明，这两类信道均可跨多实例GPU（MIG）分区被利用——而MIG本意正是通过硬件强制手段为共置租户提供强隔离保障。借助概念验证攻击，我们构建了两种跨MIG实例的隐秘信道：一种基于缓存驱逐（eviction）的信号传递方式，速率达约8500比特/秒；另一种基于迁移延迟（migration-delay）的信号传递方式，速率达约8100比特/秒。此外，基于中断的信道还可对不同大语言模型（LLM）的推理工作负载及CPU SPEC2017基准测试进行指纹识别，并能以较高精度估计LLM推理过程中所处理的提示（prompt）长度。上述结果揭示了硬件管理的异构内存系统中存在的安全缺口，并对当前启用MIG的多租户GPU部署所宣称的隔离保障提出了质疑。

## Abstract
NVIDIA's Grace Hopper (GH200) superchip represents a new generation of heterogeneous computing, tightly integrating a 72-core Arm-based CPU with a Hopper GPU on a single module via a high-bandwidth, cache-coherent interconnect. By eliminating the conventional PCIe bottleneck for CPU-GPU data movement, this design establishes a unified memory domain that scales to the capacities demanded by generative AI and high-performance computing (HPC) workloads. The architecture also introduces hardware-assisted page migration: driven by access counters, the system dynamically promotes frequently accessed pages from host CPU memory to GPU DRAM to improve memory locality. We study the security of this emerging architecture against new side- and covert-channel attacks targeting its page migration support. We analyze counter-driven migration across both the hardware mechanisms and the UVM driver's interrupt-handling pipeline, and identify two side-channel vulnerabilities: one rooted in the shared structure of access counters, and the other in the driver's response to migration interrupts. We further show that both channels are exploitable across Multi-Instance GPU (MIG) partitions, a feature intended to provide strong, hardware-enforced isolation between co-located tenants. Using proof-of-concept attacks, we build covert channels that reach roughly 8,500 bits per second through eviction-based signaling and 8,100 bits per second through migration-delay-based signaling across MIG instances. The interrupt-based channel also fingerprints inference workloads across distinct large language models (LLMs) and CPU SPEC2017 benchmarks, and estimates the prompt length processed during LLM inference with high accuracy. These results expose a security gap in hardware-managed heterogeneous memory systems and call into question the isolation guarantees of current MIG-enabled multi-tenant GPU deployments.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：随着生成式AI与HPC工作负载对大内存、低延迟CPU-GPU协同的依赖加剧，GH200等新型异构架构被广泛部署于云环境；而MIG是当前主流的GPU多租户隔离方案。本文质疑：当隔离边界从传统微架构资源（如缓存、TLB）延伸至**内存管理硬件状态（访问计数器）与内核驱动共享流水线**时，是否仍能维持安全承诺？  
- **背景关键点**：
  - GH200采用NVLink-C2C互连，支持ATS（Address Translation Service）与硬件访问计数器，可自动将高频访问的系统内存页（64 KB粒度）迁移到GPU DRAM。
  - 计数器默认阈值为256次访问，达阈值后触发中断，由UVM驱动执行迁移。
  - MIG设计目标是为不同租户分配逻辑上完全隔离的GPU资源（计算单元、内存带宽、寄存器），但**计数器硬件池与UVM驱动内核模块（`nvidia.ko`）均为全局共享**。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：利用GH200页迁移机制中两类**跨MIG共享的侧信道载体**构建隐蔽通信与指纹识别能力：
  - **载体一：物理地址映射的共享访问计数器池**（Hardware Counter Sharing）  
    - 计数器按物理地址（PA）哈希分配，共256个，组织为8组×32个（set-associative结构）；每组对应一个2 MB物理地址范围。
    - 攻击者通过构造“驱逐集”（Eviction Set）——即大量访问其他2 MB区域页面，使目标计数器被LRU策略淘汰——从而控制目标页是否触发迁移（二值信号）。
  - **载体二：UVM驱动中断处理流水线的竞争延迟**（Migration Delay Contention）  
    - 迁移中断由UVM驱动“top half + bottom half”分阶段处理，共享工作队列与锁（如`mmap_lock`）。
    - 当受害者进程执行GPU操作（如kernel launch）、CPU内存操作（如`munmap`）或OS调度活动时，会阻塞迁移处理，导致迁移延迟∆显著增加（单位：系统内存访问次数）。
    - 攻击者通过测量∆变化（高/低延迟）编码比特。

- **关键技术流程（文字描述）**：
  - **驱逐型隐通道（Eviction-based Covert Channel）**：
    1. 发送方（Spy）在指定512 MB大页内构造多个驱逐集（每个集含32个2 MB对齐页）；
    2. 发送‘1’时，轮询访问一个驱逐集（避免自身页面被误迁）；发送‘0’时静默；
    3. 接收方（Victim）对目标页分两阶段访问：先`N−δ`次（如254次），等待D时间让发送方响应，再`δ`次（如2次）；随后检测是否发生迁移（迁移→‘0’，未迁移→‘1’）。
  - **延迟型隐通道（Migration-Delay-based Covert Channel）**：
    1. 发送方达到迁移阈值（256次）后不等待完成，持续制造竞争（如频繁调用`cudaMalloc`/`cudaFree`）；
    2. 接收方精确测量从第256次访问到迁移启动的时间（以系统内存访问次数计）；
    3. 高延迟（>30次访问）→‘1’，低延迟（≤30次）→‘0’。

## 6. 主要结论与发现

- **核心结论**：GH200的硬件辅助页迁移机制在设计上**未考虑多租户隔离需求**，导致两类共享资源成为MIG隔离的“阿喀琉斯之踵”：
  - **访问计数器硬件池**在MIG实例间全局共享，且按物理地址哈希分配，构成可预测的驱逐信道；
  - **UVM驱动中断处理流水线**（尤其是`mmap_lock`争用）暴露可观测延迟，形成软件级侧信道；
- **量化发现**：
  - 驱逐信道：**8,500 bps**（1 set, 1.5% error）→ **15,500 bps**（2 sets, ~5% error）；
  - 延迟信道：**8,100 bps**（4% error），但稳定性较差（仅~50%成功率）；
  - LLM指纹识别：**最高94%准确率**（LightGBM）；
  - LLM prompt长度估计：**MAE = 4.6 tokens**（R² = 0.92）；
  - CPU负载识别：**最高89%准确率**（LightGBM/XGBoost）；
- **根本启示**：异构内存系统的安全不能仅依赖“计算单元隔离”，**内存管理硬件状态与内核驱动共享逻辑同样构成关键攻击面**。

## 8. 不足与局限
