## 摘要
AI-RAN正推动无线接入网（RAN）处理与人工智能（AI）工作负载在GPU加速计算平台上的融合，涵盖从GPU加速基站到云原生基础设施的各类部署。尽管GPU加速提升了虚拟化RAN功能的执行效率，但对时延敏感的基带处理所消耗的算力会随业务负载动态变化，从而产生瞬态空闲GPU资源，可供同节点部署的AI应用复用。现有GPU共享机制依赖粗粒度硬件分区或静态资源分配，难以在保障严格时序约束的前提下，适应以RAN时隙为单位的工作负载波动。本文提出ScaleRAN——一种面向AI-RAN的节点级弹性GPU资源管理运行时。ScaleRAN利用NVIDIA Green Contexts技术，通过一组预创建的GPU分区梯度，动态划分流式多处理器（SM）资源，供RAN与AI工作负载共享，从而实现开销极低、以RAN时隙为粒度的资源重分配。该运行时天然支持开放无线接入网（O-RAN）O-Cloud部署，即一类典型的AI-RAN部署场景。为驱动上述资源重分配，我们设计了一种受Kubernetes自动扩缩容机制启发的响应式控制器，以及一种基于分位数回归与共形预测的前摄式控制器。此外，我们基于NVIDIA Aerial开发了LDPCSim——一款GPU加速的工作负载生成器，以支持可复现的评估。实验结果表明，预测式细粒度GPU分区方案可在满足RAN时隙级截止时间的前提下，显著提升同节点AI工作负载可获得的GPU资源，验证了弹性GPU共享在未来AI-RAN平台中的实用性。

## Abstract
AI-RAN is driving the convergence of radio access network (RAN) processing and artificial intelligence (AI) workloads on GPU-enabled computing platforms, ranging from GPU-accelerated base stations to cloud-native infrastructures. While GPU acceleration improves the efficiency of virtualized RAN functions, the computational demand of latency-critical baseband processing varies with traffic load, creating transient spare GPU capacity that can be reclaimed by co-located AI applications. Existing GPU-sharing mechanisms rely on coarse-grained hardware partitioning or static resource allocation, limiting their ability to adapt to slot-level workload fluctuations while preserving strict timing requirements.   This paper presents ScaleRAN, a node-local runtime for elastic GPU resource management in AI-RAN. ScaleRAN leverages NVIDIA Green Contexts to dynamically partition Streaming Multiprocessors (SMs) between RAN and AI workloads through a ladder of pre-created GPU partitions, enabling low-overhead resource reallocation at RAN slot granularity. The proposed runtime naturally supports Open-RAN (O-RAN) O-Cloud deployments, one representative AI-RAN deployment scenario. To drive these reallocations, we propose a reactive controller inspired by Kubernetes autoscaling and a proactive controller based on quantile regression and conformal prediction. We also develop LDPCSim, a GPU-accelerated workload generator built on NVIDIA Aerial for reproducible evaluation. Results show that predictive fine-grained GPU partitioning satisfies slot-level RAN deadlines while increasing the GPU resources available to co-located AI workloads, demonstrating the practicality of elastic GPU sharing for future AI-RAN platforms.

- **研究背景**：
  - O-RAN WG6 正推动“O-Cloud Enhancements for AI Applications”，要求云原生平台支持 RAN 与 AI 的弹性协同；
  - GPU 成为虚拟化 gNB 和边缘节点的关键加速器，但其高价值与稀缺性要求最大化利用率；
  - 粗粒度静态划分（如固定 MIG 实例）造成严重资源浪费（如图6中“positive SM difference”达 26.6 SM 平均过配），而粗放式并发（如 MPS）缺乏隔离性，易引发干扰。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：构建一个**节点级轻量运行时（ScaleRAN）**，以 **Streaming Multiprocessor（SM）为最小调度单元**，通过预配置、可快速切换的 GPU 分区梯度（ladder），在 RAN slot 边界完成零中断、低开销的资源重分配，实现“RAN 保 deadline + AI 拓展资源”的双赢。

- **关键技术细节**：
  - **Green Contexts（GC）驱动的弹性 SM 分区**：
    - 利用 NVIDIA GC 提供的驱动层轻量抽象，在初始化阶段预创建一组互斥 SM 分配剖面（profile ladder）：  
      $\Pi = \{ \pi_0, \pi_1, ..., \pi_{P_{\max}} \}$，其中 $\pi_p = (S^{\text{RAN}}_p, S^{\text{AI}}_p)$，满足 $S^{\text{RAN}}_p + S^{\text{AI}}_p = S_{\text{total}}$，且 $S^{\text{RAN}}_p$ 随 $p$ 单调递增。
    - 运行时仅通过切换 profile 索引（写入共享内存），使后续 kernel 自动绑定至对应 GC，**无需设备重配置、不中断正在执行的 kernel**（因 CUDA kernel 不可抢占，切换生效于下一次 launch）。
  - **双模 autoscaling 控制器**：
    - **响应式控制器（K8S-React）**：受 Kubernetes HPA 启发，按比例缩放：  
      $\hat{S}^{\text{RAN}}_t = S^{\text{RAN}}_{p_{t-1}} \cdot \frac{d_{t-1}}{D}$，再映射到满足 $S^{\text{RAN}}_p \geq \hat{S}^{\text{RAN}}_t$ 的最小 profile；上扩立即执行，下扩引入 $H$-slot 稳定窗口防抖。
    - **前摄式控制器（Proactive）**：基于**分位数回归 + 共形预测**构建安全上界：
      - 使用 LightGBM 训练 $\tau$-quantile 回归模型 $g_\tau(x_t, p)$，输入为 radio descriptors（PRBs、MCS、layers、coded bits、base graph、当前 profile）→ 输出第 $\tau$ 分位解码延迟估计 $\hat{d}^{(\tau)}_t(p)$；
      - 应用**单侧分裂共形预测（split conformal prediction）**校准：在 calibration set 上计算非一致性得分 $r_i = \max(0, d_i - \hat{d}^{(\tau)}_i)$，取第 $\lceil (n_{\text{cal}}+1)(1-\alpha) \rceil$ 大值 $q_\alpha$，得安全上界 $U_t(p) = \hat{d}^{(\tau)}_t(p) + q_\alpha$；
      - 选择满足 $U_t(p) \leq D$ 的最小 profile $p_t$。
  - **LDPCSim 工作负载生成器**：基于 NVIDIA Aerial cuPHY 构建，严格遵循 3GPP NR 物理层规范（PRB→TB size→LDPC segmentation），支持多 UE 动态流量（正弦/三角/突发），输出真实、可复现的 slot-level GPU 解码负载与 latency 测量（含 host-device sync 开销）。

## 3. 实验设计

- **数据集 / 场景**：
  - **训练数据集**：10⁵ 条 trace，每条 3000 slots，覆盖单 UE PRB/MCS/MIMO 扫描 + 密集多 UE 场景；
  - **评估数据集**：8 条独立 trace，每条 10,000 slots，含强正弦波 + 突发流量混合模式；前 500 slots 用于共形校准，后 9500 slots 用于 policy 评估。
- **Benchmark（核心指标）**：
  - **Deadline success rate**：slot 内 LDPC 解码 latency ≤ 0.5 ms 的比例；
  - **Mean SM regret**：实际分配 SM 数与理论最优（oracle）分配之差的均值，衡量资源浪费；
  - **AI throughput / latency**：ResNet/YOLOv4/Mistral/gemma 等模型在释放资源下的性能提升。
- **对比方法**：
  - K8S-React（纯响应式）；
  - K8S-Proact（响应式控制律 + 预测延迟替代实测）；
  - Proactive（直接选 profile，无比例控制）；
  - 预测变体：Mean（期望值）、Quantile（P90/P95/P99）、Conformal Quantile（校准后 P99）。

## 6. 主要结论与发现

- **核心结论**：ScaleRAN 首次实现了 **slot-granularity、low-overhead、predictive-safe 的 GPU 弹性共享**，在 **100% 满足 RAN 截止时间前提下，显著提升 AI 可用 GPU 资源**（Fig.9 中 Conformal P99 Proactive 方案将 mean SM regret 降至 4.80，较 K8S-React 的 8.69 降低 45%，即 AI 多获约 37% SM）；
- **关键发现**：
  - **预测优于响应**：Proactive（Conformal P99）deadline success 达 99.96%，远超 K8S-React 的 98.22%；
  - **安全上界设计有效**：共形校准使 empirical coverage 精确匹配 target（Fig.8），避免欠保护；
  - **AI-RAN 干扰由双重因素决定**：不仅是 inference latency，更是 **kernel duration 相对于 slot 的占比 + SM footprint**（Fig.10：MLP-40L-2048D 因长 kernel + 满 SM 占用导致严重干扰，而 ResNet-152 虽 latency 长但 SM 利用率低，干扰小）；
  - **O-RAN 集成自然**：ScaleRAN 作为 node-local O-Cloud service，通过 O1/O2 接口与 SMO 对接，符合 O-RAN WG6 架构演进方向。

## 7. 优点

- **架构轻量高效**：基于 GC + shared memory 的 cooperative design，仅需应用侧微修改（wrap stream selector），兼容 PyTorch/TensorRT/HF Transformers，避免复杂 CUDA 拦截；
- **控制粒度精准**：以 RAN slot 为调度单位，与物理层处理节奏天然对齐，保障 timing determinism；
- **预测机制鲁棒安全**：分位数回归 + 共形预测组合，兼顾模型表达力与统计保证，解决 ML 预测不确定性带来的 deadline violation 风险；
- **评估严谨可信**：LDPCSim 基于真实 Aerial cuPHY，输入符合 3GPP 规范，latency 测量包含端到端开销，结果具强工程参考价值；
- **生态适配前瞻**：原生支持 O-RAN O-Cloud，定义了 rApp/SMO 协同框架，直指产业落地路径。
