## 摘要
代码审查往往不仅需要判断局部正确性，还需进行更深层次的设计推理。在成熟的软件系统中，评审者必须识别待审变更所引入的设计权衡，比较不同实现方案，并评估其与项目特有约束条件的兼容性。我们将此类任务称为“面向设计意识的代码审查”。然而，现有自动化审查方法主要聚焦于缺陷检测与正确性验证，而历史评审讨论中积累的设计知识却难以被有效复用。
为应对上述挑战，我们提出了 DesignLore——一种知识增强型方法：它从历史评审讨论中抽取设计决策，将其组织为一个自适应的设计分类体系，并复用相关历史知识以指导当前代码审查。此外，我们构建了 DesignReviewBench，一个源自真实补丁-评审历史的基准数据集，用于系统性地评估面向设计意识的代码审查能力。实验结果表明，当前代码智能体在面向设计意识的审查任务上仍面临巨大挑战，其中性能最强的基线方法在设计权衡识别任务上的 F1 值仅为 0.213；相比之下，DesignLore 达到了 0.259 的 F1 值，相对提升达 21.6%，且该优势在不同智能体系统与不同骨干模型上均保持稳定。这些结果凸显了设计意识在代码审查中的关键作用，并验证了挖掘与复用历史设计知识以支撑该任务的巨大潜力。

## Abstract
Code review often requires reasoning beyond local correctness. In mature software systems, reviewers must recognize design trade-offs introduced by a proposed change, compare alternative solutions, and reason about their compatibility with project-specific constraints. We refer to this problem as design-aware code review. However, existing automated review approaches primarily focus on defects and correctness, while the design knowledge accumulated in historical review discussions remains difficult to reuse.   To address these challenges, we present DesignLore, a knowledge-augmented approach that extracts design decisions from historical review discussions, organizes them into an adaptive design taxonomy, and reuses relevant historical knowledge to guide code review. We further construct DesignReviewBench, a benchmark derived from real patch-review histories for systematically evaluating design-aware code review. Our evaluation shows that design-aware review remains challenging for current coding agents, with the strongest baseline achieving an F1 of only 0.213 on design trade-off detection. In comparison, DesignLore achieves an F1 of 0.259, a 21.6% relative improvement, and consistently delivers gains across different agent systems and backbone. These results highlight the importance of design-aware review and demonstrate the potential of recovering and reusing historical design knowledge to support it.
