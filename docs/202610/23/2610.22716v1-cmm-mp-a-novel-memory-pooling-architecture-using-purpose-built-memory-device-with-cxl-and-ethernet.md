## 摘要
CXL内存模块—内存池化（CMM-MP）提出了一种新型内存池化架构，以满足新兴内存密集型工作负载的独特需求。该设备是业界首款专为内存池化设计的硬件，融合了计算快速互联（CXL）的优势以及以太网在可扩展性和成本方面的优势。多个CMM-MP设备协同工作，可提供灵活、可组合且解耦的内存扩展方案。CMM-MP无需修改现有GPU/CPU应用，即可为其提供数百TB级别的内存容量。内存池以大容量逻辑聚合内存的形式对外呈现，所有内存池发现、组合及后端网络数据通路任务均由设备完全卸载执行。CMM-MP同时支持内存池化与内存共享两种使用模式，可实现2.7微秒的应用延迟和最高达23 GB/s的内存吞吐量。我们的评估表明，CMM-MP在延迟和吞吐量方面显著优于基于RDMA的解决方案。此外，我们还利用CMM-MP评估了Valkey+YCSB和DiskANN等真实应用场景。

## Abstract
CXL Memory Module - Memory Pooling (CMM-MP) introduces a novel memory pooling architecture to meet the unique requirements of emerging memory-intensive workloads. This industry-first, purpose-built memory-pooling device combines the benefits of Compute Express Link (CXL) with the scalability and cost advantages of Ethernet. Multiple CMM-MP devices together provide a flexible, composable, and disaggregated memory expansion solution. The CMM-MP enables 100s of TB capacity for GPU/CPU applications without modifications. The memory pool is exposed as a large-capacity logical aggregate memory, with all pool discovery, composition, and backend network datapath tasks fully offloaded to the device. CMM-MP supports both memory pooling and sharing usage modes. It provides an application latency of 2.7 us and up to 23 GB/s of memory throughput. Our evaluations demonstrate that CMM-MP significantly outperforms RDMA-based solutions in latency and throughput. We also evaluated real-world use cases of Valkey+YCSB and DiskANN using CMM-MP.

## 1. 核心问题与整体含义（研究动机和背景）

- **内存墙加剧，传统架构难以为继**：随着大语言模型（LLM）、图计算、云原生服务等内存密集型负载爆发式增长，单节点内存容量严重受限于物理空间、功耗、散热及PCIe/CXL拓扑约束，导致内存利用率低、过度配置（over-provisioning）普遍，TCO居高不下。
- **解耦需求迫切但现有方案存在根本矛盾**：
  - RDMA方案需侵入式软件栈改造（显式远程调用、上下文切换开销），延迟高、编程复杂；
  - 纯CXL交换机方案受限于机架级部署、成本高昂、扩展性差（物理距离、交换延迟、带宽瓶颈）；
  - CXL-over-Ethernet仅保留点对点低延迟，不支持多主机共享的“真正池化”语义；
- **核心目标**：构建一种**无需应用修改、硬件全卸载、兼具CXL语义透明性与以太网规模经济性**的内存池化基础设施，实现百TB级、微秒级、可动态组合的解耦内存资源池。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：提出**CMM-MP（CXL Memory Module – Memory Pooling）专用硬件设备**，将CXL Type 3内存设备与200G以太网后端深度融合，通过片上FPGA+ARM协处理器实现**全硬件卸载的池发现、地址映射、可靠传输与一致性管理**，对外暴露为标准NUMA内存。

- **关键技术细节**：
  - **双平面架构**：
    - *控制平面*：ARM Cortex-A53子系统运行固件，自主完成设备发现（广播Discovery帧→排序Chip ID→分配Device ID）、全局池地址映射表（PAMT）构建与下发；
    - *数据平面*：CXL子系统（Gen5x8）解析MemRd/MemWr请求；Ethernet子系统（双200Gbps端口）负责无损传输；DDR子系统（3×16GB DDR4通道）提供本地介质访问。
  - **地址映射机制（关键公式）**：
    - 归一化主机地址：`NHA = HA − HDM_Base`（式1）；
    - PAMT查表：12-bit索引定位4K项PAMT条目，返回`Device ID`与`Device Pool Offset`；
    - 目标内存偏移：`Memory Offset = NHA − Device Pool Offset`（式2）；
    - 若`Device ID == Self ID`，则本地访问；否则经以太网转发至目标CMM-MP。
  - **以太网可靠性保障**：
    - Transport层实现序列号（SN）、位图（64-bit bitmap + overflow counter）机制，支持乱序/丢包/重复包检测与重传；
    - 控制面（ARM）与数据面（CXL/Ethernet）使用不同Ethertype隔离，避免干扰。

## 6. 主要结论与发现

- CMM-MP达成**2.7 μs端到端应用延迟**与**23 GB/s峰值吞吐**（MP-R），显著优于RDMA（64B读延迟3.17 μs，8MB带宽23 GB/s）；
- 在Valkey+YCSB中，MP-R相较系统内存**吞吐下降<30%，延迟增加≈30%**（除高写入Workload D外），证明其对生产数据库负载高度可用；
- DiskANN中，MP-R吞吐达SSD的**3倍以上**，且接近系统内存基线，验证其对AI向量检索的强支撑能力；
- 全硬件卸载设计使CMM-MP**无需任何应用/OS修改**，完全兼容CXL Type 3、devdax/fsdax接口；
- 支持**池化（exclusive allocation）与共享（concurrent access）双模式**，并保证原子性（上层软件负责一致性）。

## 7. 优点

- **首创性与工程落地性**：业界首个融合CXL语义与以太网规模的专用内存池硬件，非纯软件或协议栈方案；
- **极致卸载**：池发现、地址映射（PAMT）、可靠传输（SN+bitmap）、MAC配置等全部由设备固件完成，零主机干预；
- **成本效益比突出**：复用成熟200G以太网生态（交换机、光模块），规避昂贵CXL交换机与定制线缆；
- **灵活部署**：支持聚合式（专用内存机柜）与分布式（各服务器自带CMM-MP）两种池化拓扑；
- **验证扎实**：涵盖微基准、工业级数据库、前沿AI算法三类负载，且包含24小时稳定性测试。

## 8. 不足与局限

- **GPU生态集成缺失**：未验证与GPU Direct Memory Access（GDMA）、CUDA Unified Memory或NVLink/CXL GPU互连的协同，对主流AI训练场景支持存疑；
- **规模验证有限**：实验仅用4台CMM-MP（288GB池），未展示百TB级（如32+设备）下的延迟扩展性与PAMT管理开销；
- **一致性模型简化**：仅保证原子性，不保证顺序一致性（ordering），依赖上层软件同步（如锁、消息），增加开发复杂度；
- **能效与热设计未披露**：作为高带宽（400Gbps后端）+ FPGA+ARM+DDR的复合设备，功耗、散热特性及对数据中心PUE影响未量化；
- **安全与多租户隔离未讨论**：未涉及内存池跨租户隔离（如IOMMU/SMMU支持）、加密传输、故障域隔离等云环境关键需求。
