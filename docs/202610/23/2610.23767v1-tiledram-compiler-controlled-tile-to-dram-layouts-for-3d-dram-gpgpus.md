## 摘要
现代GPU编译器为张量到线程及片上资源的映射提供了丰富的布局抽象，但计算单元本地（CU-local）的3D DRAM架构却缺乏一种对应抽象，用以指定操作数Tile数据在DRAM地址空间内的排列方式。若缺少此类抽象，现有DRAM地址映射下的常规数据放置策略将导致结构化Tile访问遭遇严重的行缓冲区冲突。本文提出TileDRAM——一个编译器-运行时协同的工具链，它将Tile到DRAM的布局引入为一种编译器可见的DRAM放置抽象。TileDRAM将GPU线性布局抽象从计算侧映射目标扩展至DRAM放置坐标，并依据每个Tile访问签名选择布局，以重复出现的Tile局部访问行为作为特化单元。由于行缓冲区局部性依赖于有序的请求历史，TileDRAM在固定DRAM地址映射下，通过评估候选布局的行缓冲区行为来筛选最优布局。所选布局下的访问通过常规地址运算即可实现，无需新增地址重映射硬件或指令集架构（ISA）支持。在Accel-Sim/Ramulator2平台上对108个混合专家（MoE）前馈网络（FFN）案例的全迹重放实验中，TileDRAM将请求加权的行冲突率从75.7%降至15.2%，并取得1.77倍的几何平均加速比。将六个迹重定向至六种不同的3D DRAM组织结构后，在相同编译器抽象下获得2.20倍的几何平均加速比。在RTX 3090上，地址变换仅引入0.17%的几何平均开销（相对于恒等映射）。

## Abstract
Modern GPU compilers expose rich layout abstractions for mapping tensors to threads and on-chip resources, but compute-unit-local (CU-local) 3D DRAM architectures lack a corresponding abstraction for specifying how operand-tile data are   arranged within the DRAM address space. Without such an abstraction, conventional placement under the existing DRAM address mapping can subject structured tile accesses to severe row-buffer conflicts. We present TileDRAM, a compiler-runtime   toolchain that introduces tile-to-DRAM layouts as a compiler-visible abstraction for DRAM placement. TileDRAM extends the GPU Linear Layout abstraction from compute-side mapping targets to DRAM placement coordinates and selects layouts per   tile access signature, using recurring tile-local access behavior as the specialization unit. Since row-buffer locality depends on ordered request history, TileDRAM evaluates candidate layouts through their row-buffer behavior under fixed   DRAM address mappings. Accesses under the selected layouts are realized through ordinary address arithmetic, without new address-remapping hardware or ISA support. In full-trace replay on Accel-Sim/Ramulator2 across 108 mixture-of-experts   (MoE) feed-forward network (FFN) cases, TileDRAM reduces the request-weighted row-conflict rate from 75.7% to 15.2% and achieves a 1.77x geomean speedup. Retargeting six traces to six 3D DRAM organizations yields a 2.20x geomean speedup   under the same compiler abstraction. On an RTX 3090, address transformation adds 0.17% geomean overhead over identity.

# TileDRAM 论文中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **根本矛盾**：在 CU-local 3D DRAM 架构（即每个计算单元直连专属近存堆栈）中，GPU 编译器虽已具备强大的 *tile-level compute-side layout* 抽象（如 Triton/CuTe 的线性布局），但**缺乏对 tile 数据在 DRAM 地址空间中如何物理排布的编译器可控机制**。  
- **后果严重**：现有固定 DRAM 地址映射（如 RoBaTiCoCh）下，结构化 tile 访问流（如 MoE FFN 中密集 GEMM 的 tiled load）会反复触发不同行（row），导致高达 **75.7% 的请求加权行冲突率**（row-conflict rate），即大量请求需 precharge + activate，严重浪费高带宽本地路径。
- **架构动因**：CU-local 设计（如 OpenAI Jalapeño、Stratum）将 3D DRAM 堆栈紧耦合于逻辑芯片，提供 TB/s 级内部带宽，但该带宽能否被高效利用，**完全取决于软件能否引导访问序列匹配 DRAM 行缓冲区局部性**——而传统硬件地址映射是全局、静态、粗粒度的，无法适配 tile 粒度的动态访问模式。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：将 **“tile 如何映射到 DRAM 地址”** 提升为编译器一级的显式、可编程、可优化的抽象（`tile-to-DRAM layout`），并基于 *tile 局部访问行为的稳定性* 实现细粒度、低成本特化。
- **关键技术**：
  - **Tile Access Signature（访问签名）**：作为布局选择的最小稳定单元，由三元组 `(κ, ρ, χ)` 定义：
    - `κ`（tile 配置）：形状 `(BM, BN, BK)`、流水线级数 `num_stages`、warp 数 `num_warps`；
    - `ρ`（操作数属性）：位置（lhs/rhs）、数据类型、内存步长（stride）、行列主序（layout）；
    - `χ`（有序访问序列）：归一化后的 tile-local 活跃 lane 地址序列 `S_θ = (r₀, ..., r_{N−1})`。
  - **Tile-to-DRAM Linear Layout（线性布局）**：将 GPU 的 `F₂-linear layout` 代数扩展至 DRAM 地址空间，定义为一个可重用的矩阵 `W_sem ∈ F₂^{m×n}`，其分块 `[W_C; W_D; W_R]` 分别决定：
    - `W_D`：映射到行缓冲域（domain，如 `tier,bank` 对）；
    - `W_R`：映射到该域内的具体行（row）；
    - `W_C`：映射到行内列/字节偏移（column/byte offset）。
  - **布局选择算法（PLAN 阶段）**：
    1. **枚举域投影 `W_D`**：在目标 DRAM 组织约束下（如 8-tier, 16-bank → `b=7` bit domain ID），枚举有限的位选择/XOR 候选；
    2. **构建重用核 `K`**：对每个 `W_D`，计算同域内连续请求的地址差 `Δᵢ = rᵢ ⊕ r_pred(i)`，求解最大权重 `c`-维子空间 `K ⊆ ker(W_D)`，使 `∑_{Δ∈K} w(Δ)` 最大（即最大化行命中）；
    3. **重构完整布局 `W_sem`**：基于 `K` 构造 `W_R`，再补全 `W_C` 保证满秩；
    4. **有序选择**：按 `lexicographic objective J(S,W) = (N_conf, −cov(S,W_D), nnz(W_phys))` 排序，优先最小化冲突数，其次最大化跨域覆盖，最后最小化地址变换复杂度。
  - **实现无硬件依赖**：所有布局通过标准地址算术（shift/mask/XOR/add）在编译期生成，运行时仅需 `APPLY` 阶段对源地址做 `GF(2)` 变换，**无需新 ISA、无需地址重映射硬件、无需修改内存控制器**。

## 6. 主要结论与发现

- **核心结论**：**DRAM 数据布局可成为编译器可控的、独立的性能优化维度**，无需改动硬件地址映射即可释放 CU-local 3D DRAM 的全部带宽潜力。
- **关键发现**：
  - Tile 局部访问行为（signature）是稳定、可复用的特化单元，远优于 trace-level 或 tensor-level 特化；
  - 在 MoE FFN 场景下，TileDRAM 将 **request-weighted row-conflict rate 从 75.7% 降至 15.2%（80.0% 降低）**；
  - 实现 **1.77× geomean kernel speedup**（108 cases），且加速比与 baseline 内存 stall 占比强相关（`r=0.90`）；
  - **跨 6 种 DRAM 组织重定向后仍获 2.20× geomean speedup**，证明其架构无关性；
  - **运行时开销可忽略**：RTX 3090 上地址变换仅引入 **0.17% geomean 开销**，中位数 <0.01%；
  - **离线合成成本可控**：单例平均约 6 分钟 CPU 时间，可离线完成并复用于海量运行时实例。

## 7. 优点

- **零硬件侵入性**：纯软件方案，兼容现有 GPU ISA 和 DRAM 控制器，**部署门槛极低**；
- **编译器友好与抽象统一**：复用并扩展成熟的 `Linear Layout` 代数（F₂），与 Triton/CuTe/Gluon 生态无缝集成，程序员无需接触底层地址位；
- **细粒度与高适配性**：以 tile signature 为单位特化，精准匹配 MoE 中专家异构、动态调度的访问模式；
- **强可移植性与可预测性**：同一 layout 模板可复用于所有满足 signature 的 tile 实例；重定向实验验证其跨组织有效性；
- **严谨的方法论与完备的验证**：从数学建模（kernel reduction）、算法设计（fixed-domain solver）、到工程实现（APPLY lowering）、再到全系统仿真（Accel-Sim/Ramulator2），形成完整闭环，并提供开源 artifact 支持。

## 8. 不足与局限

- **场景覆盖局限**：实验聚焦于 **MoE FFN 的 tiled GEMM**，尚未验证在 attention、convolution、sparse kernels 或非 MoE 的 dense transformer 上的效果；
- **多 CU 协调缺失**：当前设计为单 CU-stack 对，未解决跨 CU 的数据放置协调（如 cache-coherent sharing 或 NUMA-aware placement）；
- **物理硬件验证空白**：所有结果基于高保真仿真（Ramulator2），**尚未在真实 3D DRAM 硬件（如 HBM4 stack 或 Raptor ASIC）上实测**；
- **动态调度假设**：依赖于 grouped GEMM 的 tile-local 访问序列可被准确捕获，若 runtime 调度引入不可预测的 interleaving（超出 tile-local 范畴），可能影响效果；
- **离线开销敏感性**：虽然单例 6 分钟可接受，但对于需要频繁 re-tune 的 auto-tuning 流程，此开销可能成为瓶颈（文中未探讨增量合成或在线学习）。
