## 摘要
细粒度混合专家（MoE）已成为扩展大语言模型的事实标准架构。然而，专家负载的动态不平衡会导致严重的内存波动，从而降低训练效率。现有系统依赖静态内存预分配：要么过度预分配，导致GPU内存在正常执行期间闲置；要么预分配不足，在负载激增时引发内存溢出崩溃及代价高昂的手动回滚。为应对这些挑战，我们提出BaGuaLu-2——一种面向大规模MoE模型训练的系统，通过灵活的内存供给机制彻底消除上述两难困境。BaGuaLu-2将内存分配从静态、一次性的调优决策转变为持续且细粒度的控制过程，可按需为每个训练批次精确分配激活内存。此外，它通过系统级优化完全抵消了动态管理带来的开销。BaGuaLu-2展现出卓越的可扩展性：在12,288块GPU上训练参数量达10400亿的模型，同时维持超过2 EFlops的计算吞吐与35%的MFU（模型浮点利用率）。相较于当前最先进的系统，BaGuaLu-2的平均吞吐量分别比Megatron-Kuai和AdaPipe高出1.14倍和1.13倍。

## Abstract
Fine-grained Mixture-of-Experts (MoE) is the de facto architecture for scaling large language models. However, dynamic expert load imbalance causes severe memory fluctuations that degrade training efficiency. Existing systems rely on static memory provisioning: they either over-provision, leaving GPU memory idle during normal execution, or under- provision, inviting out-of-memory crashes and costly manual rollbacks when load spikes occur. To address these challenges, we propose BaGuaLu-2, a large-scale MoE training system that eliminates this dilemma through flexible provisioning. By transforming memory allocation from a static, one-time tuning choice into a continuous and fine-grained control. BaGuaLu-2 grants exact activation memory on demand for each training batch. Furthermore, it offsets any dynamic management overhead through system optimizations. BaGuaLu-2 demonstrates exceptional scalability, training a model with 1040 billion parameters across 12,288 GPUs while sustaining over 2 EFlops at 35% MFU. Compared with state-of-the-art systems, BaGuaLu-2 delivers 1.14x and 1.13x average throughput improvements over Megatron-Kuai and AdaPipe, respectively.

## 1. 核心问题与整体含义（研究动机和背景）

- **根本挑战**：细粒度 MoE（如 DeepSeek-V3、Kimi-K2）采用动态稀疏路由（top-k token-to-expert），导致专家负载呈现**偶发性、高幅值内存尖峰**（实测：2.9% 迭代中出现最高达 2.6× 的 imbalance rate），引发**激活内存（activation memory）剧烈波动**。
- **现有系统困境**：主流训练框架（如 Megatron-Kuai、AdaPipe）采用**静态内存配置**——要么“过配”（预留冗余内存防 OOM，常态下 GPU 显存闲置，MFU 持续偏低）；要么“欠配”（追求高 MFU，但遇尖峰即 OOM，需人工重启+保守重配，恢复成本高达 284 秒/次）。
- **关键洞察**：该波动源于 MoE 架构本质——token 独立采样 + 输入数据分布漂移 → 有限样本方差 → 不可避免的 per-batch 激活内存差异。因此，**静态策略与动态压力存在根本性错配**，必须转向运行时按批调控。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：将激活内存管理从“静态预设”升级为“**连续、细粒度、按微批次（micro-batch）动态供给**”，实现“零闲置、零 OOM”的弹性显存利用。
- **三大关键技术**：
  - **Activation Memory Modeling（§IV）**：构建统一的激活代价模型（∆t, ∆m），量化每个算子（LayerNorm/Linear/MoE-dispatch）的时间与内存开销，并建模不同缓解策略（recompute/offload/quantize）的“缓解带宽”（mitigation bandwidth），形成 roofline 式策略选择依据。
  - **Adaptive Activation Provisioning（§V-A）**：  
    - *Pipeline-aware budget assignment*：根据 pipeline 阶段（warmup/steady/cooldown）与实时 MoE imbalance rate，动态计算每微批次内存预算（Algorithm 1）。Warmup 阶段均摊剩余容量；Steady 阶段复用前序 backward 释放内存。  
    - *Roofline-guided iterative mitigation*：在预算约束下，贪心迭代选择单算子缓解策略（Algorithm 2），优先采纳单位内存节省带来最大收益者，并显式检测并规避**异构缓解冲突**（如多精度冲突、多设备冲突）。
  - **Fused Dual-Batch Execution（§V-B）**：  
    - 将相邻 forward/backward 微批次的算子（F/B/O/R 四类）视为独立流，通过轻量级动态规划（DP）求解最优交错执行顺序，将缓解操作（offload/reload/recompute）隐藏于硬件空泡（hardware bubble）中，消除其对关键路径的影响。
