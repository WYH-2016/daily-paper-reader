## 摘要
同步数据并行训练通常为每个计算秩（rank）分配相同数量的样本，即使各样本的计算开销相差数个数量级。对于变长模型而言，这种做法会将输入长度的差异转化为设备空闲时间，因为每一步训练都需等待本地批次中计算开销最大的那个样本完成。我们提出“批次开销前瞻”（Batch Cost Lookahead, BCL）——一种无需跨秩协调的数据加载策略：该策略在每个秩上维护一个有界大小的本地缓冲窗口，并将其重划分为若干固定样本数的子批次，使得各子批次的预估开销尽可能均衡。BCL 严格保持训练器对样本总数的契约约束，且既不需要跨秩元数据交换，也不需要运行时修改。在基于公开工作负载分布的仿真中，启用 BCL 可将各秩预估批次开销的变异程度最高降低 82.8%。在八块 H200 GPU 上针对 13 个 NeMo-RL 监督微调语料库的实验表明，采用秩本地 BCL 的训练速度比池化式首次适配递减算法（pooled MFFD）快 1.050 至 1.167 倍。在内部序列工作负载上的编译后 H200 实测结果表明，从单节点至四节点配置下，BCL 相比打包执行方式可获得 1.197 至 1.343 倍的加速比。我们还识别出一个内存可行性边界：对高方差或易触发内存溢出（OOM）的数据，采用 p99 开销作为上限可预先截断异常值，再由 BCL 对剩余样本进行均衡分配。这些结果表明，大量由样本开销差异导致的负载不均衡问题可在数据加载器层面予以消除；同时也厘清了在何种情形下仍需依赖数据预处理或更广泛的跨秩协调机制。

## Abstract
Synchronous data-parallel training usually assigns every rank the same number of records, even when record costs vary by orders of magnitude. For variable-length models, this converts input variation into idle time because each step waits for its most expensive rank-local batch. We present Batch Cost Lookahead (BCL), a coordination-free data-loading policy that buffers a bounded rank-local window and repartitions it into fixed-cardinality packs with balanced estimated cost. BCL preserves the trainer's record-count contract and requires neither cross-rank metadata exchange nor runtime modification. In simulation over public workload distributions, enabling BCL reduces per-rank estimated batch-cost variability by up to 82.8%. Across 13 NeMo-RL SFT corpora on eight H200 GPUs, rank-local BCL runs 1.050 to 1.167 times faster than pooled MFFD. Compiled H200 measurements on an internal sequence workload show speedups of 1.197 to 1.343 times over packed execution from one to four nodes. We also identify a memory-feasibility boundary: a p99 cap for high-variance or OOM-prone data bounds outliers before BCL balances the rest. These results show that substantial variable-cost imbalance can be removed at the data-loader boundary, while clarifying when data preparation or broader coordination is still necessary.

## 1. 核心问题与整体含义（研究动机和背景）

- **同步训练中的隐性负载失衡问题**：在同步数据并行（SDP）训练中，各 rank 被强制分配相同数量的样本（如每步 B 个），但变长序列（如 LLM 输入）导致实际计算开销（token-wise + quadratic attention）差异巨大；最慢 rank 决定全局步长，其余 rank 空转，形成显著 idle time。
- **现有方案的局限性**：
  - 序列打包（packing）、变长 kernel 只减少 *单批次内 padding 浪费*，不解决 *跨 rank 批次间工作量不均*；
  - 全局负载均衡方法（如 Libra、WLB-LLM）需跨 rank 通信、元数据交换或重调度，引入协调开销与系统耦合，违背“轻量部署”原则。
- **核心科学问题**：仅利用每个 rank 本地已知的、有界窗口内的样本信息（无需通信、不改模型/collective），最多能消除多少由样本成本异质性引起的同步瓶颈？

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：在 rank-local 数据加载器中引入**有界前瞻（bounded lookahead）+ 成本感知重分组**，将固定大小的本地缓冲窗口（`W = K × B` 个样本）动态划分为 `K` 个等大小（各 `B` 个样本）、总开销尽可能均衡的“pack”，从而平抑每步的 `max-pack-cost`。

- **关键设计**：
  - **固定基数契约（Fixed-cardinality contract）**：输出始终为 `B` 样本/step，兼容现有训练框架（如 FSDP、loss normalization），无需修改优化器或 collective。
  - **成本建模**：采用 `c(ℓ) = α·min(ℓ, ℓ_max) + β·min(ℓ, ℓ_max)²`，线性项表征 token-wise 运算，二次项表征 self-attention；`ℓ_max` 为预设 p99 截断阈值（内存可行性前置保障）。
  - **调度算法（Algorithm 1）**：
    1. 对窗口内 `W` 个样本按 `−c(ℓ)`（降序）+ tie-breaking key 排序；
    2. 初始化 `K` 个空 pack，贪心分配：每次选当前负载最小且未满的 pack 放入下一记录；
    3. 迭代优化：在最重与最轻 pack 间执行确定性“重–轻交换”，仅当严格降低 `max-pack-cost` 时接受；
    4. 输出 `K` 个 `B`-size packs，按确定性 shuffle 后依次发射。

- **无协调本质**：全程仅读取本 rank 的 shard 流，不访问其他 rank 数据、不交换任何 cost 或 length 元数据、不修改 global batch 构造逻辑。

## 6. 主要结论与发现

- **BCL 显著缓解同步瓶颈**：
  - 仿真中 `CV_pack` 降低 **81.4–82.8%**，`ρ−1`（straggler excess）降低 **81.0–83.9%**；
  - NeMo 实测：BCL vs pooled MFFD 加速 **1.050–1.167×**（+5.0% to +16.7%）；vs default packing（`K=1`）加速 **1.004–1.305×**，且使 CodeParrot/OpenWebMath 等 OOM 场景成功运行；
  - H200 多节点：1→4 节点加速比达 **1.197–1.343×**（step time ↓16.5–25.5%），验证 scale-out 收益递增。
- **边界条件清晰**：
  - **内存可行性先行**：p99 截断是 BCL 前置必要条件；5 个语料需 proactive p99 cap，4 个因 OOM 必须 cap；
  - **可解性判据**：提出 `η = m / \bar{C}`（最大记录成本 / 平均包成本）与 `δ = max_r \bar{C}_r / \bar{C}_{all}`（rank 窗口均值离散度）两个诊断指标（Table 1），指导何时用 cap、reshard 或全局协调。
- **正交性与兼容性**：BCL 与 packing、variable-length kernels、token-budget batching 完全正交，可叠加使用。

## 7. 优点

- **系统友好性极强**：零跨 rank 通信、零 runtime 修改、零模型/collective 侵入，仅需替换数据加载器局部逻辑，**生产部署门槛极低**。
- **理论与实践结合紧密**：从 NP-hard makespan 问题出发，采用工程可行的 LPT+swap 启发式，并通过 `η`/`δ` 诊断框架将抽象复杂度转化为可操作的运维决策（Table 1）。
- **评估维度全面**：覆盖仿真（isolated scheduling）、框架集成（NeMo）、工业级多节点（H200）、内存/精度/稳定性（AUC、peak mem），证据链完整。
- **问题定义精准**：聚焦“coordination-free”这一被忽视的实用象限，填补了“纯本地优化”与“强全局协调”之间的方法空白。

## 8. 不足与局限

- **数据分布假设限制**：所有实验基于 **i.i.d. 或近似 i.i.d. 分片**（shards），未测试强非平稳流（如时序 drift、用户群体突变）或严重 skew 分片（`δ ≫ 1`）下的鲁棒性；此时 Table 1 明确指出需 reshard 或全局协调。
- **截断策略未深入**：p99 cap 是经验性启发，未探索 adaptive cap、learned truncation 或 loss-aware截断对下游任务质量的影响（NeMo 实验仅报告 AUC 微小变化，未分析生成质量）。
- **硬件依赖未泛化**：全部实测基于 H200，未在 A100/H100/V100 等架构验证，其 kernel 性能、memory bandwidth 差异可能影响 BCL 收益。
- **训练动态效应未覆盖**：未研究 BCL 引入的样本重排序是否影响 curriculum learning、收敛稳定性或最终模型质量（仅报告 AUC，缺乏 loss curve、perplexity、human eval）。
- **长尾成本建模简化**：成本函数 `c(ℓ)` 忽略 kernel launch overhead、memory fragmentation、non-uniform memory access（NUMA）等系统层因素，实际 GPU time 与 `c(ℓ)` 存在建模误差。
