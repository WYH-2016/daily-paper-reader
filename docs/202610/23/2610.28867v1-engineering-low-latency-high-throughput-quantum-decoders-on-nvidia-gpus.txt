# Engineering Low-Latency, High-Throughput Quantum Decoders on NVIDIA GPUs 

Stefano Markidis, Luca Pennati, Ivy Peng 

KTH Royal Institute of Technology 

Abstract —We design and optimize a quantum error cor-rection (QEC) decoder for NVIDIA GPUs, combining Relay belief propagation, a state-of-the-art message-passing algorithm, with order-zero ordered statistics post-processing. Our imple-mentation uses CUDA Graphs to control GPU execution, stops updates for converged samples, and collects unresolved samples in queues for post-processing. We optimize sparse traversal through coalesced message accesses, prefetching, and register reuse, and accelerate binary post-processing with warp-level collectives. In addition, mixed FP16–FP32 arithmetic and INT8 quantization reduce message storage and traffic while retaining accuracy using accumulators at higher precision. We evaluate surface, hypergraph product, and bivariate bicycle code workloads on NVIDIA A100 and GH200 data-center GPUs and a commodity RTX 5080. On the bivariate bicycle code at error probability 0.003, INT8 halves amortized decoding time relative to indepen-dently tuned FP32 with a negligible logical error rate increase on RTX 5080. With independent syndrome batches submitted back-to-back to concurrent decoder instances, RTX 5080 delivers 91% of GH200’s highest measured throughput with an 8.9 × shorter median submission-to-correction latency. The combination of performance optimization, mixed precision, INT8 quantization, and concurrent decoder instances opens a path toward QEC decoder clusters built from commodity GPUs. 

Index Terms —NVIDIA GPUs, quantum error correction 

I. I NTRODUCTION 

Fault-tolerant quantum computing requires classical de-coders that process measurement data at least as fast as it is generated [1]. Quantum error correction (QEC) encodes one or more logical qubits in a code block of physical qubits. Re-peated parity measurements, called stabilizer checks , produce a 

syndrome : a binary vector recording deviations from expected correct outcomes. The decoder infers a correction from this vector. As the number of logical qubits (each encoded across multiple physical qubits) grows, each measurement round gen-erates more syndrome data, increasing the required aggregate decoding throughput. Independent decoding requests provide parallel work that the classical system can exploit to sustain this higher data rate. From an HPC perspective, the QEC computational work-load is akin to sparse graph processing. QEC graphs have nodes with different numbers of neighbors. Each edge update requires few arithmetic operations, and iteration counts depend on the measured syndrome. Reconfigurable FPGAs and cus-tom ASICs can tailor their logic and memory organization to these operations [2]. GPUs combine high memory bandwidth with thread parallelism across graph updates and independent syndrome samples, allowing memory accesses to overlap. In this work, we evaluate the latency, throughput, and logical accuracy of optimized GPU decoding to assess whether GPUs can serve as credible, programmable devices for QEC workloads. QEC decoding exposes GPU parallelism within each syn-drome sample and across independent decoding requests. Each sample requires repeated sparse graph traversal, followed by a binary linear solver if the iterative decoder reaches its iteration limit without converging. This section introduces the QEC terminology and decoding algorithms needed to develop the GPU decoder. We begin with the sparse graph representation of circuit-level QEC workloads, then describe Relay-BP message passing and the OSD-0 binary solver. 

QEC Sparse Matrices and Decoding Graphs. The core data structure in graph-based QEC decoding is a sparse binary check matrix H. It records how possible errors affect measured check outcomes: each column represents an error variable and each row a parity check. An entry is one if that error flips the corresponding check outcome, and zero otherwise. The matrix defines a bipartite Tanner graph, with separate node sets for checks and variables and one edge per nonzero (see Fig. 2). Row and column traversals access the neighborhoods of checks and variables, respectively. To infer a correction from syndrome data, the decoder needs a physical noise model specifying possible errors and their probabilities. Examples include depolarizing noise, which introduces random bit flips, phase flips, or both, and measure-ment errors, which flip recorded bits. In circuit-level decoding 

(the model we use in this work), this model assigns error probabilities to individual gates, initialization, idle intervals, and measurements in the circuit used to repeatedly measure stabilizer checks. A detector produces a bit indicating whether the parity of selected measurement outcomes differs from its expected error-free value. QEC simulation tools such as

Message-Passing QEC Decoders. Message-passing decoders infer error patterns through repeated local updates on the decoding graph. The computational pattern is similar to neighborhood aggregation in graph neural networks: nodes gather messages from neighbors, combine them, and send updated information along graph edges (Fig. 2). In belief propagation (BP), messages represent error reliabilities as log-likelihood ratios. Positive values favor no error, negative values favor an error, and larger magnitudes indicate greater confidence. The channel prior is the initial reliability derived from each variable’s error probability. In this work, we use Relay-BP, which adds memory to BP updates [4]. Each iteration executes two dependent ker-nels: (i) Parity/min-sum gathers variable-to-check messages over each check neighborhood and generates check-to-variable messages. For each check-to-variable message, we exclude the incoming message from the recipient variable. The outgoing sign bit is the XOR of the syndrome bit and the remaining incoming sign bits. We use the smallest remaining magnitude as the outgoing confidence: the least certain neighbor limits the strength of the check’s inference. Min-sum approximates BP’s nonlinear check update with sign and minimum reduc-tions. Normalization scales the minimum magnitude down to compensate for the approximation’s overestimate of message confidence. (ii) In Belief/Relay , we form a posterior , the updated reliability estimate for each error variable. We com-bine a weighted blend of the channel prior and previous pos-terior with the sum of incoming check messages. Subtracting the recipient check’s incoming contribution gives the outgoing variable-to-check message. Relay-BP groups iterations into 

legs , each with an iteration limit. A new leg restarts message passing from the channel prior and initializes Relay memory with the preceding leg’s final posterior. After each iteration, we make a hard decision by converting each posterior into a bit: 1 for a predicted error (negative posterior) and 0 otherwise. We retire a sample, stopping further updates, when this candidate reproduces its measured syndrome. Samples unresolved after the final leg proceed to OSD-0. OSD-0: A Binary Linear Solver. Samples unresolved by message passing are passed to OSD-0 [5], which addresses the inverse problem defined by H: the measured syndrome is known, while the error pattern is unknown. For unresolved samples, we compute the residual syndrome , the XOR differ-ence between the measured syndrome and that predicted by the BP candidate. We sort variables by increasing absolute posterior and use Gaussian elimination to select linearly inde-pendent columns of H in this order. These columns form a basis in which we express the residual syndrome, identifying which error bits to toggle. This ordering prioritizes adjustments to the least confident BP estimates. Order zero constructs a sin-gle candidate correction (higher-order OSD explores additional bit flip combinations at greater computational cost). The solver operates over GF(2) (the Galois field with two elements, 0 and 1), where addition and subtraction are XOR and multiplication is AND. Binary Gaussian elimination selects nonzero pivots and cancels entries through XOR operations. Packing vectors into machine words allows each instruction to update many binary entries simultaneously, i.e., a 64-bit XOR updates 64 entries. Ordered pivot selection (choosing linearly independent columns from least to most reliable) introduces sequential dependencies, while sample-dependent elimination compli-cates load balancing on GPUs. Hybrid implementations have consequently retained OSD on the CPU even when message passing runs on the GPU. Efficient GPU execution requires parallelism across packed words and unresolved samples while preserving the reliability order of basis selection. Sorting and elimination also make an OSD-0 invocation substantially more expensive than a message-passing iteration. Resolving more samples through Relay-BP therefore reduces costly post-processing. III. P ERFORMANCE OPTIMIZATION ON NVIDIA GPU S

This section presents the kernel, numerical, and execu-tion optimizations of the NVIDIA GPU decoder. We follow the execution blocks of the instantiated CUDA Graph in Fig. 3 to explain sparse traversal, memory reuse, device-side convergence control, and cooperative binary elimination. For the message-passing stages, we detail reduced-precision FP16 arithmetic, mixed FP16-FP32 arithmetic, and INT8 quantiza-tion, explaining the choice of message formats, accumulated state, and intermediate precision. 

Data Layout and Thread Mapping. All syndrome samples in a batch share the same decoding graph. We store its connectivity once using compressed sparse row (CSR) lists of variables per check and compressed sparse column (CSC) indexing of incident edge IDs per variable. Maintaining both views gives each update direct neighborhood access, avoiding searches through the full edge list. Both directed message arrays share a common check-major edge numbering and use an edge-major layout, with samples contiguous within each edge. Per-variable state follows the same sample-contiguous ordering. Threads processing adjacent samples traverse the same adjacency list and access contiguous message and state values, coalescing memory accesses across the batch. The Parity/min-sum update traverses each check neigh-borhood twice: first to compute sign parity, the two small-est magnitudes, and the minimum’s index, then to generate outgoing messages. In both passes, our optimized variant prefetches two messages into registers before processing either value, software-pipelining loads ahead of dependent arithmetic to increase memory-level parallelism. We advance message pointers by the batch stride to avoid repeated wide edge-offset calculations. In Belief/Relay , we eliminate repeated loads by retaining incoming messages in registers for variables with at most four neighbors. Each cached value contributes to the posterior sum and is then subtracted to form the corresponding outgoing message. Larger neighborhoods use a general traversal. We further reduce arithmetic and control overhead by precomputing Relay coefficients, using fused multiply-add instructions, and applying branchless clipping. 

Convergence and Work Scheduling. As a further opti-mization, we encode the dependent iteration kernels in a preinstantiated CUDA Graph and evaluate convergence on the GPU, avoiding host readbacks between iterations. Each Relay leg contains a conditional WHILE node that repeats the updates while samples remain active and the iteration limit has not been reached. A kernel evaluates this condition using warp ballots and a shared-memory reduction. We retire converged samples by marking their entries inactive in a fixed-capacity sample-ID array. Subsequent kernels skip inactive IDs, preserving message and state offsets throughout Relay-BP. Before the OSD-0 phase, we compact unresolved sample IDs into a contiguous fallback queue. The solver uses these IDs to access message, posterior, and syndrome arrays at their original offsets, avoiding payload movement. We bound OSD-0 workspace through chunked execution because per-sample basis storage grows approximately quadratically with the num-ber of checks. A conditional IF node executes each chunk only when the unresolved count exceeds that chunk’s starting queue index. Kernels compute the unresolved count and evaluate all conditional nodes; the host stages inputs and launches the graph. For concurrent execution, each decoder instance owns a CUDA stream, private buffers, and an instantiated graph. Independent batches can advance through Relay legs and OSD-0 at different rates, exposing kernels from multiple decoder instances to the GPU scheduler. 

Warp-Level Collectives. We parallelize neighborhood reduc-tions and binary-vector operations within each syndrome sam-ple using cooperating warp lanes. Cooperative check variants distribute each check-sample pair across a group of lanes and use shuffle reductions to combine sign parity and the two smallest magnitudes. In OSD-0, lanes update different packed words of a candidate vector and use shuffle reductions to select pivots. These operations exchange intermediate values through registers, avoiding shared-memory staging for the reductions.

For elimination, we assign one 256-thread block to each unresolved sample and pack matrix columns into 64-bit words, so each XOR updates 64 binary entries. Reduced Precision, Mixed Precision, and Quantization. 

As a final optimization, we develop reduced-precision FP16, mixed FP16-FP32, and INT8-quantized Relay-BP kernels to reduce message storage and traffic. Each iteration reads and writes both directed edge-message arrays. For the bivariate bicycle workload used in this study, with a batch of 128 samples, these arrays occupy about 178 MiB in FP32 and 45 MiB in INT8. Because each concurrent decoder instance maintains private messages, the fourfold reduction also low-ers the memory cost of concurrency. We select storage and arithmetic widths according to the numerical requirements of each update [6]. Check updates combine signs and minimum magnitudes, with outgoing messages bounded by clipping. Variable updates sum incoming messages and retain estimates across iterations, producing posterior magnitudes that can ex-ceed the message clipping threshold. Our mixed-precision im-plementation stores messages and Relay memory in FP16 and accumulates and stores posterior beliefs in FP32. Finding 4 Warp-level collectives accelerate QEC decoding. 

Warp-level collectives expose parallelism inside the small re-ductions and binary-vector updates that recur throughout QEC. Register exchanges between lanes reduce serial work and shared-memory staging for local reductions, complementing concurrency across independent syndromes. OSD-0 demonstrates the impact at both kernel and de-coder levels. On A100, a standalone benchmark with 810 checks and 640 synthetic residuals achieves 20-21 × faster packed reduction than a one-thread-per-sample scalar refer-ence. Extending the production warp-cooperative solver to eight concurrent candidate reductions gives a further 2.25 ×

solver-kernel speedup. Candidates are finalized in reliability order, incorporating preceding basis updates and preserving sequential OSD-0 selection. For BB90 at p=0.005, FP32, and B=256, complete-decoder time decreases by 8.8%, with unchanged logical-error counts. Profiling shows less barrier waiting and higher scheduler issue activity. The cooperative INT8 BP phase applies the same principle to message passing. Lane groups partition each check neigh-borhood and use warp shuffles to combine sign parity and the two minimum message magnitudes before computing outgoing messages. 

Finding 5 Binary Tensor Core instructions provide modest gains in binary algebra. QEC post-processing relies on binary linear algebra, making Tensor Cores an interesting ac-celeration target. NVIDIA’s 1-bit matrix multiply-accumulate instructions process packed binary tiles using bitwise AND and population counts. Extracting each count’s parity produces the binary matrix product. On A100, we compare this Tensor Core path with packed AND and population-count operations. For 65,536 products with 8×8 output tiles and inner dimension 128, kernel time decreases from 30.77 to 27.43 μs, a 1.12 ×

L2 reuse and DRAM utilization differ across tuned GPU configurations. Table IV compares BB90 ker-nel profiles at each GPU’s selected INT8 batch size. For each kernel, L1 hit rates remain similar across devices; the larger memory-system differences appear in L2 reuse and DRAM utilization. The green Belief/Relay L2 entries on A100 and GH200 show 74% and 65% hit rates, compared with the red RTX 5080 entry at 36%. The bold DRAM entries distinguish relative utilization from absolute band-width. RTX 5080 reaches 55% DRAM SOL while transferring 0.52 TB/s; GH200 transfers 1.13 TB/s at 28% SOL. The selected RTX configuration consumes a larger fraction of its available bandwidth, while GH200 sustains more than twice the transfer rate at lower relative DRAM utilization.  

> Finding 7

Memory dependencies limit instruction issue at high occupancy. On A100, Parity/min-sum reaches 97% occupancy, yet records 51% issue activity and 1.32 eligible warps per scheduler (both highlighted in red). Belief/Relay 

achieves 65% issue activity and 2.05 eligible warps per scheduler (green) at 73% occupancy. Across all three GPUs, 

Belief/Relay consistently supplies more eligible warps and achieves higher issue activity than Parity/min-sum . The highlighted long-scoreboard ratios connect this readiness gap to memory dependencies: A100 records 23.77 warp stall cycles per issue-active cycle for the Parity/min-sum kernel (red), compared with 9.61 for the Belief/Relay kernel (green). Resident warps waiting for memory operands cannot advance their dependent instructions.  

> Finding 8

Batch size and stream concurrency control the latency-throughput tradeoff. Fig. 5 identifies which com-binations of batch size and stream count deliver the highest measured throughput within a given response-time constraint under burst input. The Surface workload on GH200 illustrates the benefit of concurrency at small batch sizes. At B = 16 ,increasing the stream count from one to four raises throughput from 3.01 to 9.02 kdecodes/s, a 3× gain, while median response increases from 5.93 to 7.78 ms. Concurrent batches supply more independent work while preserving the small batch size of each request. Larger batches show diminishing throughput returns near the frontier’s upper endpoint. At 

S = 4 , doubling B from 128 to 256 increases throughput from 22.18 to 24.10 kdecodes/s, an 8.7% gain, while response increases from 23.05 to 42.72 ms, an 85% increase. For a 10 ms median-response requirement, the best measured configuration is B = 32 , S = 4 , delivering 14.30 kdecodes/s at 8.94 ms.  

> Finding 9

Commodity GPUs can outperform HPC GPUs within a response-time requirement. Comparing the frontiers under fixed response-time limits changes the GPU ranking. Across all three workloads, every A100 frontier point has an RTX 5080 configuration delivering higher throughput with a shorter response. RTX also exceeds GH200’s throughput under short response-time limits. For Surface within 10 ms, RTX delivers 20.11 kdecodes/s compared with GH200’s 14.30 kde-codes/s, a 41% advantage. For BB90 within 20 ms, the corre-sponding rates are 5.95 and 4.03 kdecodes/s, a 48% advantage. GH200 reaches the highest measured throughput for all three code families, with larger batches extending its frontier toward higher throughput and longer responses. On BB90, GH200 delivers 6.50 kdecodes/s with a 156 ms median response; RTX delivers 5.95 kdecodes/s at 17.6 ms, providing 91% of that throughput with an 8.9-times shorter response. RTX uses six concurrent decoder instances processing 16-sample batches, compared with GH200’s four instances processing 256-sample batches. RTX’s efficiency at small batch sizes is key to this latency-throughput advantage. Small batches provide shorter units of work. Each completion returns corrections and releases a de-coder instance for the next request, while other instances con-tinue executing. Multiple instances supply parallelism across requests, allowing RTX to sustain high throughput with less work within each batch. A100 and GH200 benefit more from larger batches to reach high throughput, increasing the work each request must complete before returning corrections. BP with OSD is an established decoder for quantum low-density parity-check codes [5]. Relay-BP advances message-passing accuracy through memory and relay ensembling [4]; its strong circuit-noise results motivate our choice of algo-rithmic foundation. Localized statistics decoding parallelizes post-processing by using binary solvers on local regions of the decoding graph [9]. B´ ascones et al. [2] study FPGA/ASIC implementations of BP and OSD, including elimination cost. On GPUs, Ferraz et al. [10] implement BP syndrome decoding on commodity hardware. CUDA-Q QEC provides BP/OSD and Relay-BP decoders [11], and Wang et al. [12] investigate parallel BP retries and windowed/streaming execution. Mau-rya et al. [13] study provisioning and scheduling of shared decoders under bursty demand. Knapen et al. [14] develop qLDPC hardware predecoders that reduce OSD invocation and additional Relay-BP legs. VII. C ONCLUSION 

We designed and implemented a Relay-BP/OSD-0 decoder entirely on NVIDIA GPUs, combining specialized kernels, convergence control with CUDA Graphs, ordered multi-warp binary elimination, reduced and mixed precision, and quan-tization. We evaluated decoding time, logical recovery, and latency-throughput tradeoffs for concurrent decoding requests across three circuit-level code families and three GPU architec-tures. Relatively small concurrent batches allow a commodity RTX GPU to approach GH200’s peak burst throughput with substantially shorter responses. These results support commodity GPU clusters as pro-grammable HPC infrastructure for QEC, combining compet-itive decoding throughput with low-latency responses. Such clusters could become standard components of fault-tolerant quantum computers, serving as programmable decoding accel-erators alongside quantum controllers. ACKNOWLEDGMENT
