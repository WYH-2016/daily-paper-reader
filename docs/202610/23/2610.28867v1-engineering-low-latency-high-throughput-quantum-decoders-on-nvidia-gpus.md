## 摘要
我们为NVIDIA GPU设计并优化了一种量子纠错（QEC）解码器，将前沿的消息传递算法——中继置信传播（Relay belief propagation）与零阶有序统计后处理（order-zero ordered statistics post-processing）相结合。本实现采用CUDA Graphs控制GPU执行流程，对已收敛的样本停止迭代更新，并将未解决的样本收集至队列中进行后处理。我们通过合并的消息访问（coalesced message accesses）、预取（prefetching）和寄存器复用优化稀疏图遍历过程，并利用线程束级（warp-level）集体操作加速二值化后处理。此外，混合使用FP16-FP32浮点运算及INT8量化，在借助高精度累加器保障解码精度的同时，显著降低消息存储开销与内存带宽占用。我们在NVIDIA A100与GH200数据中心GPU以及消费级RTX 5080显卡上，评估了表面码（surface code）、超图积码（hypergraph product code）和双变量自行车码（bivariate bicycle code）三类负载。在双变量自行车码、物理错误率为0.003的测试条件下，RTX 5080上采用INT8量化后的平均解码时间相比独立调优的FP32实现降低一半，且逻辑错误率仅出现可忽略的微小上升。当以连续方式向多个并发解码器实例提交独立的综合症批处理（syndrome batches）时，RTX 5080实现了GH200所测最高吞吐量的91%，同时将从提交到完成纠错的中位延迟缩短了8.9倍。性能优化、混合精度计算、INT8量化与并发解码器实例的协同应用，为构建基于商用GPU的量子纠错解码器集群开辟了可行路径。

## Abstract
We design and optimize a quantum error correction (QEC) decoder for NVIDIA GPUs, combining Relay belief propagation, a state-of-the-art message-passing algorithm, with order-zero ordered statistics post-processing. Our implementation uses CUDA Graphs to control GPU execution, stops updates for converged samples, and collects unresolved samples in queues for post-processing. We optimize sparse traversal through coalesced message accesses, prefetching, and register reuse, and accelerate binary post-processing with warp-level collectives. In addition, mixed FP16-FP32 arithmetic and INT8 quantization reduce message storage and traffic while retaining accuracy using accumulators at higher precision. We evaluate surface, hypergraph product, and bivariate bicycle code workloads on NVIDIA A100 and GH200 data-center GPUs and a commodity RTX 5080. On the bivariate bicycle code at error probability 0.003, INT8 halves amortized decoding time relative to independently tuned FP32 with a negligible logical error rate increase on RTX 5080. With independent syndrome batches submitted back-to-back to concurrent decoder instances, RTX 5080 delivers 91% of GH200's highest measured throughput with an 8.9x shorter median submission-to-correction latency. The combination of performance optimization, mixed precision, INT8 quantization, and concurrent decoder instances opens a path toward QEC decoder clusters built from commodity GPUs.

- **量子纠错（QEC）是实现容错量子计算的基石**：需实时处理不断产生的稳定子测量结果（syndrome），推断并施加纠错操作；解码器必须满足“**吞吐 ≥ 量子硬件生成 syndrome 的速率**”，否则纠错链路失效。
- **传统硬件瓶颈突出**：FPGA/ASIC虽高效但缺乏可编程性与生态支持；CPU难以满足高并发、低延迟需求；现有GPU解码器普遍存在**访存不规则、精度冗余、控制开销大、未充分利用并发性**等问题。
- **核心问题**：如何在**商用NVIDIA GPU**（尤其是消费级显卡）上构建**低延迟（latency-critical）、高吞吐（throughput-scalable）、高精度（accuracy-preserving）且可部署**的端到端QEC解码器？

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：以**Relay-BP + OSD-0**为算法基座，围绕GPU微架构特性进行全栈优化——从**执行控制 → 稀疏计算 → 数值表示 → 并发调度**逐层提效，而非仅加速单个kernel。

- **关键技术细节**：
  - **执行控制优化**：
    - 使用 **CUDA Graphs** 封装完整解码流程（Relay-BP迭代、收敛判断、样本退休、OSD-0触发），消除主机-GPU同步开销；
    - **设备端收敛控制**：在GPU上用warp ballot + shared-memory reduction动态统计活跃样本数，WHILE节点实现无主机干预的条件迭代；
    - **样本早停与紧凑队列**：收敛样本标记为inactive跳过后续计算；未收敛样本ID被**致密压缩（dense compaction）** 进入fallback queue，避免数据搬移。
  
  - **稀疏图遍历优化**：
    - **双视图CSR+CSC存储**：同时支持check-centric与variable-centric邻域访问，消除索引搜索；
    - **coalesced edge-major layout**：消息数组按边主序、样本连续排布，使同一批次中相邻线程访问内存连续；
    - **两级预取（two-way prefetch）**：在Parity/min-sum kernel中提前加载2个消息至寄存器，掩盖访存延迟；
    - **寄存器缓存（register cache）**：对度≤4的变量，复用寄存器中已加载的消息参与后验计算与出站消息生成。

  - **二值后处理加速（OSD-0）**：
    - **ordered multi-warp elimination**：使用CUB radix sort分块排序（2048变量/块）+ merge-path合并；按可靠性顺序分组处理8个候选变量，重用同一basis并行消元，兼顾顺序性与并行性；
    - **warp-level collectives**：利用`__shfl_*`指令在warp内完成sign parity、min magnitude等reduce，避免shared memory staging。

  - **数值优化（混合精度与量化）**：
    - **INT8量化方案（Fig. 4）**：可靠性×6后四舍五入为INT8（范围[−120,120]），clip at ±20；**消息存储/传输用INT8，累加用INT32，后验/Relay memory用INT16**；保留高精度中间态保障OSD-0排序质量；
    - **FP16-FP32混合**：消息存FP16，后验累加与存储用FP32；FP16 kernel则全程FP16（含half2初始化）；
    - **归一化min-sum scaling**：在INT8输出前用宽整型中间结果补偿近似误差。

  - **并发执行模型**：
    - 每个decoder instance独占1个CUDA stream、私有buffer与instantiated CUDA Graph；
    - 多实例间解耦，支持不同batch独立推进至Relay-BP或OSD-0阶段，由GPU scheduler动态调度。

## 6. 主要结论与发现

- **Finding 1**：Batch size autotuning至关重要；BB90上B=2048比B=32快3.34×，但最优B随p变化（p=0.001时B=1024更优）。
- **Finding 3**：INT8是性价比最高选择：RTX 5080上BB90（p=0.003）解码时间减半（416→207 μs），LER仅+0.03pp；p=0.005时减幅达55.6%，LER+0.32pp。
- **Finding 4 & 5**：Warp-level collectives显著加速（OSD-0 solver提速2.25×）；Tensor Core 1-bit MAC仅带来1.12×微弱收益，实用性有限。
- **Finding 6 & 7**：RTX 5080因L2小（64 MiB）、带宽低（256-bit），更依赖DRAM（55% SOL），而GH200靠大L2（60 MiB）与高带宽（6144-bit）实现更高绝对吞吐（1.13 TB/s @ 28% SOL）；Parity/min-sum kernel受memory stall严重制约（A100 long scoreboard=23.77）。
- **Finding 8 & 9（核心突破）**：**消费级GPU可超越HPC GPU的响应能力**——RTX 5080在10ms延迟约束下Surface吞吐达20.11 kdecodes/s（GH200仅14.30），BB90在20ms下达5.95 vs 4.03；RTX以**6 streams × B=16**实现91% GH200峰值吞吐，但延迟仅17.6ms vs 156ms（**8.9×更低**）。

## 7. 优点

- **全栈协同创新**：非单一技术点优化，而是将**算法（Relay-BP/OSD-0）、编译（CUDA Graphs）、微架构（warp collectives、register cache）、数值（INT8+INT32 accumulation）、系统（concurrent streams）** 深度融合。
- **面向真实部署**：聚焦**burst load下的latency-throughput tradeoff**，提出可直接用于量子控制器的并发实例化模型（per-stream decoder instance）。
- **精度-效率平衡严谨**：INT8设计中**严格分离存储精度（INT8）与计算精度（INT32/INT16）**，并通过clip/scale/rounding规则保障OSD-0可靠性排序不失真。
- **工程落地性强**：所有优化均基于CUDA标准生态（Graphs、CUB、warp shuffle），无需定制硬件或驱动，可直接集成至CUDA-Q等框架。

## 8. 不足与局限

- **QEC码覆盖有限**：仅评估3种码（Surface/HGP/BB90），未涵盖更复杂LDPC码、color code或fault-tolerant架构（如lattice surgery）下的解码挑战。
