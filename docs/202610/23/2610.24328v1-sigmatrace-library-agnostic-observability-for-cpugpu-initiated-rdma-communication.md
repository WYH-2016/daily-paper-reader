## 摘要
RDMA 网络技术可在大规模系统中实现低延迟、高带宽的通信。尽管该技术已被广泛采用，其可观测性却严重不足。现有工具或仅针对特定通信库，或仅报告聚合统计数据，无法反映单个操作的行为细节；其中 GPU 发起的网络通信可观测性缺口尤为突出——其内核态 RDMA 操作对主机完全不可见。本文提出 SigmaTrace，一种与通信库无关的 RDMA 性能分析框架，可为 CPU 和 GPU 发起的网络通信提供细粒度、逐操作级别的可观测性。SigmaTrace 在 libibverbs/mlx5dv 层进行跟踪，该层是 InfiniBand 和 RoCE 上各类通信库共同依赖的底层接口；同时采用一种低开销的内存插桩技术，据我们所知，这是首个无需修改源码或二进制插桩即可实现 GPU 发起 RDMA 可观测性的方法。主机端跟踪在 128 卡 NCCL AllReduce 场景下引入 1.3% 的开销，在 1024 卡 RCCL 场景下开销低于 2%；在持久化内核的广度优先搜索（BFS）及混合专家（Mixture-of-Experts）推理任务中，SigmaTrace 揭示了现有性能分析器无法发现的内核态屏障扩散现象以及 2.13 倍的节点间流量倾斜。

## Abstract
RDMA networking enables low-latency, high-bandwidth communication on large systems. Despite its adoption, however, observability is lacking. Existing tools target specific communication libraries or only report aggregated data, missing per-operation behavior. The gap is widest for GPU-initiated networking, whose in-kernel RDMA operations are invisible to the host.   We present SigmaTrace, a library-agnostic RDMA profiling framework providing fine-grained, per-operation visibility for CPU and GPU-initiated networking. It traces operations at the libibverbs/mlx5dv layers, the common denominator beneath communication libraries on InfiniBand and RoCE, and employs a low-overhead memory interposition technique that, to our knowledge, gives the first observability into GPU-initiated RDMA without source patching or binary instrumentation.   Host-side tracing adds 1.3% overhead on NCCL AllReduce at 128 GPUs and under 2% on RCCL at 1024 GPUs. On a persistent-kernel BFS and Mixture-of-Experts inference, SigmaTrace exposes an in-kernel barrier spread and 2.13x inter-node traffic skew invisible to existing profilers.

# SigmaTrace 论文中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **可观测性严重缺失**：RDMA（Remote Direct Memory Access）虽已广泛用于AI训练、科学计算等高性能场景（如NCCL、UCX、NVSHMEM），但现有性能分析工具普遍缺乏对**细粒度、逐操作级通信行为**的可见性。
- **GPU发起RDMA（GIN）完全不可见**：传统工具（如Nsight Systems、NCCL Inspector、NPKit）仅能观测CPU侧API调用或内核驱动层聚合计数，而GPU线程直接构造WQE（Work Queue Element）并写入NIC门铃寄存器（UAR）的操作，在主机视角下等同于普通内存写，无API边界、无软件事件钩子，导致其**内核态通信路径彻底“黑盒化”**。
- **后果严重**：通信负载不均、QP级拥塞、屏障扩散、跨节点流量倾斜等关键性能瓶颈无法定位，尤其在Mixture-of-Experts（MoE）、持久化内核BFS等GPU-native通信密集型工作负载中，调试与优化陷入困境。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：绕过上层通信库差异，**在硬件接口层（libibverbs/mlx5dv）统一拦截**；利用GPU发起RDMA**必须通过PCIe MMIO写入NIC门铃寄存器**这一不可绕过的硬件事实，实施**用户态内存插桩（Memory Interposition）**，实现零源码修改、零二进制插桩的可观测性注入。

- **关键技术细节**：
  - **UAR内存劫持（Doorbell Hijack）**：
    - 拦截`mlx5dv_devx_alloc_uar`（分配UAR）、`cuMemHostRegister`（注册为CUDA可访问）、`cuMemHostGetDevicePointer`（获取GPU设备指针）三步初始化流程；
    - 将真实NIC UAR页替换为**CPU pinned memory页**，并将该页的GPU设备指针返回给应用；
    - GPU线程对“假UAR”的写操作（即门铃）被CPU监控线程捕获（使用`monitorx`/`umonitor`高效轮询），记录时间戳与门铃值（含QP号+生产者索引），再转发至真实UAR。
  - **WQE恢复（Deferred Batched Parsing）**：
    - 门铃值中的生产者索引指示最新WQE位置，但WQE本身可能位于纯GPU显存；
    - 采用**异步批量拷贝策略**：每次门铃触发时，启动一个CUDA流异步将对应WQE槽位拷贝至主机内存；当累积足够数量（如128个）后，同步该流并批量解析WQE内容（opcode、raddr、rkey、size等）；
    - 避免高频同步开销，同时保证语义正确性（依赖GPU内存序：WQE写必须先于门铃写，该序对替换页同样成立）。
  - **库无关多层追踪**：
    - 主动插桩`libibverbs`、`mlx5dv`（InfiniBand/RoCE）、`UCX`、`libfabric`（Slingshot/EFA），覆盖主流RDMA生态；
    - 支持三种模式：`Aggregate`（线程局部计数，零时间戳）、`Simple`（默认，记录关键事件如`ibv_post_send`，跳过高频`ibv_poll_cq`）、`Full`（全事件记录，用于深度调试）。
  - **跨节点关联分析**：
    - Profiler端使用`RDTSC`高精度计时，结合PTP协议校准各节点时钟；
    - Correlator离线合并多节点trace，重建QP拓扑、关联门铃与WQE、生成Perfetto Protobuf格式可视化轨迹（支持timeline flow arrows + custom doorbell tracks）及JSON聚合数据（QP/GPU/Node级带宽矩阵）。

## 3. 实验设计

- **基准测试（Benchmark）**：
  - **通信开销基准**：标准`NCCL all_reduce_perf`（InfiniBand平台）、`RCCL all_reduce_perf`（Slingshot平台），测量不同规模（2–128节点，8–1024 GPU）下1MB/128MB消息的AllReduce执行时间增幅。
  - **案例研究（Case Studies）**：
    - **分布式BFS**：基于NVSHMEM的持久化内核BFS，在4 GPU上运行`soc-LiveJournal1`图（4.8M顶点，68M边），验证门铃级负载不平衡与屏障扩散检测能力。
    - **MoE推理**：使用`DeepSeek-V3-0324`（671B参数，256专家）模型，通过`SGLang`在4节点16 H200 GPU上服务200个ShareGPT请求，分析数据并行（DP）下的节点间流量分布。

- **对比方法**：
  - **基线（Baseline）**：未启用任何profiling的原始运行。
  - **现有工具对照**：明确指出`Nsight Systems`（仅显示kernel块+聚合NIC计数）、`NCCL Inspector`/`Mycroft`（仅host proxy线程）、`NPKit`（需重编译+patch kernel）、`Snoopie`（全内存指令插桩，开销极高）等均**无法观测GPU内核门铃/WQE**，SigmaTrace是首个填补此空白的方案。

## 6. 主要结论与发现

- **开创性能力**：SigmaTrace是**首个无需源码修改、无需二进制插桩、无需root权限**，即可实现GPU发起RDMA**逐门铃、逐WQE级可观测性**的框架。
- **极低开销**：在128 GPU NCCL AllReduce中仅引入**1.3%** 开销；在1024 GPU RCCL中开销**<2%**；微基准显示UAR劫持本身仅增2–4%延迟，WQE解析增22–46%（属可选高保真模式）。
- **揭示隐藏瓶颈**：
  - 在BFS中首次观测到**内核级全局屏障扩散（barrier spread达30秒）**，精准定位由1D图划分导致的GPU 0 hub顶点负载不均；
  - 在MoE推理中首次量化出**2.13×节点间流量倾斜**（node2→node1 15.9GB vs node1→node2 12.3GB），暴露DP调度器在token序列长度异构性下的失效。

## 7. 优点

- **根本性创新**：提出并验证了**UAR内存插桩**这一硬件接口层可观测性范式，为GPU-native通信分析开辟新路径。
- **极致轻量与兼容**：基于`LD_PRELOAD`/`cuGetProcAddress`劫持，部署简单（`LD_PRELOAD=./sigmatrace.so`），兼容现有应用与容器环境。
- **工程完备性**：提供从实时采集（Profiler）、离线关联（Correlator）、多维可视化（Perfetto timeline + JSON matrix）到SQL分析（PerfettoSQL）的**端到端可观测性流水线**。
- **生态广覆盖**：不仅支持主流NVIDIA+Mellanox组合，还前瞻性适配AMD rocSHMEM、AWS EFA GDA、HPE Slingshot，并给出清晰移植路径。

## 8. 不足与局限

- **硬件支持范围有限**：当前**仅完整支持NVIDIA GPU + Mellanox NIC**；AMD GPU需适配ROCm驱动钩子（文中指出可行但未实现）；Broadcom Thor 2、AMD Pensando Pollara等新型NIC需重写门铃/WQE解析逻辑。
- **软件栈限制**：`LD_PRELOAD`无法拦截`libcxi`等大量使用`static inline`的库，导致HPE Cray系统可观测性降级；静态链接库亦不受支持（需转向Frida/eBPF等动态插桩）。
- **性能权衡**：`Full`模式开销显著（8–13%），仅适用于短时调试；`Simple`模式虽平衡，但仍需用户理解各模式适用场景。
- **未覆盖安全与多租户场景**：论文未讨论在共享集群、多用户隔离环境下，SigmaTrace的资源占用、隐私泄露风险或性能干扰问题。
