## 摘要
边缘设备上的检索增强生成（RAG）可在保护用户隐私的前提下实现个性化的大型语言模型（LLM）推理。然而，RAG固有的序列长度不对称性使得prefill阶段成为主要性能瓶颈。尽管在服务器系统中离线预计算KV缓存可缓解prefill开销，但多GB规模的缓存经由带宽受限的互连传输，会在端侧系统中引发严重的I/O墙问题。为应对该挑战，我们提出MemLLM——一种端到端的存储内处理（ISP）架构，其将基于预计算KV缓存的完整注意力计算流水线直接部署于固态硬盘（SSD）内部执行。MemLLM采用每通道专用加速器，以充分复用聚合的NAND闪存通道带宽，并将所有与KV缓存相关的计算任务卸载至存储侧，从而最小化PCIe数据传输量。为高效处理RAG所需的稀疏更新操作，MemLLM引入了一种融合重计算与查询的核函数，并配合硬件级过滤逻辑，使NAND读取数据量减半且完全消除写回开销。此外，MemLLM基于全局SRAM构建的状态感知规约引擎支持完全无需DRAM的数据流，从而消除了片内内存瓶颈，并将PCIe出口带宽占用严格约束在O(1)量级。配套的全栈软件栈支持ISP与主机间的异步零拷贝数据传输，并可在现代机器学习框架中实现透明化执行。在八个真实世界RAG数据集及六种端侧LLM模型上的综合评估表明，MemLLM相较GPU基线方案实现了平均4.06×的端到端加速比。

## Abstract
Retrieval-augmented generation (RAG) on edge devices enables personalized large language model (LLM) inference while preserving privacy. However, RAG's inherent length asymmetry makes the prefill phase the dominant bottleneck. While precomputing the KV caches offline alleviates the prefill cost on server systems, the multi-gigabyte caches over the narrow interconnect create a severe I/O wall for on-device systems. To mitigate this, we propose MemLLM, an end-to-end in-storage processing (ISP) architecture that executes the complete attention pipeline based on precomputed KV caches within the SSD. MemLLM utilizes per-channel accelerators to fully utilize the aggregated NAND channel bandwidth and accelerates all KV cache-related computations on the storage-side to minimize PCIe transfers. To efficiently handle the sparse updates required by RAG, MemLLM introduces a fused recomputation-query kernel paired with a hardware-based filter logic to halve the NAND read volume and eliminate write-back penalties. Furthermore, MemLLM's global SRAM-based stateful reduction engine enables a completely DRAM-less dataflow, thereby removing the internal memory bottlenecks and bounding the PCIe egress to an $O(1)$ footprint. A full-stack software stack allows asynchronous, zero-copy transfers from the ISP to the host and provides transparent execution within modern ML frameworks. Evaluated across eight real-world RAG datasets and six on-device LLM models, MemLLM achieves an average end-to-end speedup of 4.06$\times$ over the GPU baseline.

# MemLLM 论文中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：端侧（on-device）检索增强生成（RAG）面临严重的“**I/O墙**”瓶颈——预计算KV缓存（multi-GB量级）需经窄带宽PCIe（如Jetson Orin的~16 GB/s）从SSD反复加载至GPU，导致prefill阶段延迟远超计算本身；而传统服务器上有效的预计算策略在边缘设备上反而**负向加速**（实测GPU-PreCompute平均比FullCompute慢2.86%）。
- **根本成因**：
  - RAG固有**长度不对称性**：上下文常达数千token，答案仅数token（如TriviaQA达1000:1），使prefill成为主导瓶颈；
  - 预计算KV缓存**破坏跨文档注意力**，必须对约15%高偏差token（HKVD）执行**选择性重计算**（selective recomputation），引发两次全量KV缓存PCIe搬运（先读→重算→写回→再读）；
  - 边缘SoC内存受限（如8–16GB统一内存），无法容纳模型权重+全量KV缓存，迫使KV缓存**完全驻留SSD**（即“KV cache offloading”）；
  - 现有存内处理（ISP）方案（如InstAttention、AiF）仅支持decode阶段卸载或权重计算卸载，**无法处理prefill中混合GEMM/GEMV/Softmax的异构重计算负载**。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：将**整个RAG注意力流水线（prefill + decode）端到端迁移至SSD内部执行**，实现“KV缓存零出盘”，彻底消除PCIe带宽依赖。
- **关键技术**（三层I/O最小化设计）：
  - **Reduce NAND I/O（NAND读减半）**：  
    提出**融合重计算-查询核（fused recomputation-query kernel）** ——主机仅发送紧凑的`Q_fused`（含HKVD token嵌入 + 用户查询嵌入）和稀疏掩码（jagged attention mask），SSD内Stream Filter硬件逻辑实时过滤无效token，使NAND读取量减半；重计算KV直接在片上消费，**零写回**。
  - **Utilize aggregated NAND bandwidth（带宽全利用）**：  
    采用**每NAND通道专用Elastic-SIMD加速器**（非中心化单核），每个加速器含可重构数据通路：  
    - *Broadside模式*：并行处理1D decode向量（GEMV）；  
    - *Cascaded模式*：行间转发实现thin-GEMM（用于HKVD重计算），避免2D systolic阵列在稀疏场景下的严重空泡（underutilization）。
  - **Eliminate internal DRAM I/O（DRAM-less数据流）**：  
    Flash-Coordinator集成**全局SRAM（1MB）状态感知归约引擎**，直接在SRAM中完成各通道partial softmax（`m_local`, `ℓ_local`）的log-sum-exp合并，**绕过SSD控制器DRAM**；最终PCIe仅传输`Q_fused`（~512KB）和`O_final`（~512KB），**出口带宽严格O(1)**。
- **算法流程（文字版）**：  
  1. 主机执行Layer-0全计算得Layer-1 KV → 对比预计算KV生成HKVD掩码 → 发送`Q_fused`+掩码至SSD；  
  2. SSD内Stream Filter按掩码融合预计算KV与重计算KV → Elastic-SIMD分通道执行NAND-stationary tiled attention（Algorithm 1）：  
     - Phase 1（Output-stationary）：`A_tile = Q_tile × K^T_page`（寄存器累加）；  
     - Phase 2（In-situ softmax）：Vector ALU计算每行`max`/`sum(exp)` → 得`P_tile`；  
     - Phase 3（Input-stationary）：`O_partial = P_tile × V_page`（复用寄存器）；  
  3. Flash-Coordinator在SRAM中合并所有`O_partial` → 返回`O_final`；  
  4. 主机仅用`O_final`执行FFN/Projection，新KV异步追加至SSD（out-of-place，无RMW）。

## 6. 主要结论与发现

- MemLLM在8数据集×6模型上**平均端到端加速4.06×**（vs GPU-FullCompute），**4.18×**（vs GPU-PreCompute）；  
- PCIe出口带宽恒定**O(1)**（仅~512KB/step），而基线随上下文线性增长（如HotpotQA达47GB）；  
- 完整架构相较Base提速**7.1×**，其中：融合核（-38% latency）、每通道加速（-39%）、SRAM归约（-63%）贡献递进；  
- 精度损失<0.3% F1（vs CacheBlend），数学等价性获验证；  
- 功耗2.12W（<3W预算），面积0.68×于同类存内架构（AiF）；  
- 在长上下文（>48k tokens）下仍稳定运行，而AiF因GPU内存不足触发OOM；  
- 对KV压缩等正交优化**完全兼容**，仍保持2.0–4.4×加速。

## 7. 优点

- **首创性**：首个支持**端到端RAG存内推理**（含prefill重计算+decode）的硬件架构；  
- **系统级协同设计**：硬件（Elastic-SIMD/Stream Filter/SRAM Engine）+ 软件（NVMe passthrough/io_uring/PyTorch C++ extension）全栈透明集成；  
- **极致I/O优化**：NAND读减半、PCIe egress O(1)、DRAM bypass、zero-copy P2P DMA；  
- **异构负载适配**：Elastic-SIMD动态重构解决GEMM/GEMV/Softmax混合调度难题，避免2D systolic空泡；  
- **工程务实性**：基于标准NVMe vendor command（无需kernel修改）、GPUDirect RDMA已支持（Jetson Orin）、统一内存SoC天然适配。

## 8. 不足与局限

- **部署门槛**：需定制化计算型SSD（CSSD），当前商用SSD不支持；虽声明“无需kernel修改”，但依赖Linux 5.19+ io_uring NVMe passthrough，旧系统需升级；  
- **适用场景限定**：明确聚焦**预计算KV+选择性重计算+长上下文+短答案**的RAG范式；对纯生成（无检索）、内存充足（KV可驻GPU）、或答案极长（decode主导）场景收益递减（Fig 23）；  
- **未覆盖动态检索**：假设检索结果在attention前已固定（Fig 2, Sec II-B），未评估在线迭代检索（如multi-hop）与attention的联合优化；  
- **量化精度限制**：实验基于FP16，未验证INT4/INT8等超低精度下Elastic-SIMD的鲁棒性；  
- **长尾数据集验证不足**：TriviaQA-web/wik（TB级）仅用trace模拟，未在物理SSD上实测（受限于存储容量）。
