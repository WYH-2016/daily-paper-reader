## 摘要
部署深度神经网络（DNN）推理任务成本高昂，但单个任务通常难以同时占满GPU的计算单元和内存带宽。通过在同一GPU上共置多个任务实现GPU共享，可提升资源利用率，但也会带来任务间的相互干扰。现有系统通常采用二元化的计算-内存规则、独立的缩放曲线或模型级预测器来估计此类干扰。然而，这些方法对干扰的理解较为有限：它们基本未探究共置算子在软硬件层面的特性，也无法提供既可解释又准确的任务延迟 slowdown 预测。本文在流式多处理器（SM）分区场景下开展算子级干扰研究，并借助硬件性能计数器将干扰溯源至共享内存通路的竞争；结果表明，延迟 slowdown 由共置的两个算子共同决定。基于上述发现，我们提出PairSight——一种硬件感知的干扰预测器，它学习共置任务在硬件行为层面的交互模式，并可在共置前预测各任务的延迟。在包括大语言模型（LLM）在内的六种DNN模型上，PairSight在GPU共享场景下的延迟预测平均误差仅为4.3%，显著优于计算-内存强度规则的19.0%；且仅需少量样本即可泛化至未见过的模型与输入。

## Abstract
Serving DNN inference is costly, yet a single task seldom saturates both the compute units and the memory bandwidth of a GPU. GPU sharing raises utilization by co-locating several tasks on one GPU, at the cost of interference among them. Existing systems estimate this interference with binary compute-memory rules, standalone scaling curves, or model-level predictors. However, these estimates rest on a limited understanding of interference. They leave the software and hardware properties of co-located operators largely unexplored and give no slowdown prediction that is both interpretable and accurate. We conduct an operator-level study of interference under SM partitioning and use hardware counters to trace it to contention on the shared memory path, where the slowdown depends jointly on both co-located operators. Based on these findings, we propose PairSight, a hardware-aware interference predictor that learns how the hardware behaviors of co-located tasks interact and predicts the latency of each task before co-location. On six DNN models including LLMs, PairSight predicts latency under sharing with 4.3% mean error, against 19.0% for a compute-memory intensity rule, and adapts to unseen models and inputs with a few samples.

# PairSight 论文中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：在 GPU 多租户推理场景中，当多个 DNN 任务通过 SM（Streaming Multiprocessor）分区方式共享同一 GPU 时，共置算子之间因争用**共享内存路径（L2 cache + DRAM channels + interconnect）** 而产生非线性、方向性、算子特异的性能干扰（slowdown），但现有干扰建模方法严重不足。
- **研究动机**：
  - 现有方法（如 Orion/Usher 的 compute-memory 互补规则、Abacus 等模型级预测器）将干扰简化为任务级强度属性或静态查表，忽视了**算子对（operator pair）间的硬件行为耦合**；
  - 它们无法解释“为何同为 memory-intensive 的算子，在不同 co-runner 下 slowdown 差异可达 2×以上”，也无法支持细粒度调度决策（如 segment-level co-location 选择）；
  - 生产系统亟需一种**可解释、高精度、前置可预测**的 operator-level 干扰模型，以保障高优先级（HP）任务的 SLO 合规性并最大化低优先级（LP）吞吐。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：干扰不是单个算子的固有属性，而是**两个共置算子在共享内存通路上的协同争用现象**；其 slowdown 可建模为：  
  > *δ = T<sub>share</sub>(p,q) / T<sub>solo</sub>(p)*，其中 *T<sub>solo</sub>(p)* 消除了 SM 数量减少的影响，*δ* 纯粹反映并发执行开销。  
  并进一步分解为：  
  > *T ≈ T<sub>compute</sub> + N<sub>miss</sub>(L<sub>base</sub> + Q<sub>shared</sub>)*，  
  其中 *Q<sub>shared</sub>*（共享队列延迟）由 co-runner 的 DRAM 流量与 target 的 latency-hiding 能力共同决定。

- **关键技术细节**：
  - **硬件感知特征工程**：对每个算子单独 profiling，提取 8 维关键硬件计数器（来自 `Nsight Compute`）：
    - standalone duration（时延）、DRAM bytes（*N<sub>miss</sub>* 代理）、long-scoreboard stalls（未隐藏访存延迟）、LG-throttle & MIO-throttle stalls（内存压力指标）、L2 throughput/hit rate（辅助）；
    - **区分 target 与 co-runner**：分别输入两组特征，保留“谁受阻、谁施压”的语义。
  - **PairSight 模型架构**：
    - 基于 **XGBoost 回归树**（非图神经网络——原文 method 描述有误，实际为 gradient-boosted trees）；
    - 输入：target segment 与 co-runner segment 各自的 per-operator 特征序列（≤16 operators/window）+ SM 分配（p, q）+ standalone latency；
    - 输出：target segment 的 slowdown *δ̂*，最终延迟 *T̂ = T<sub>solo</sub>(p) × δ̂*；
    - **窗口组合（Window Composition）**：对长于 16 算子的 segment，按序切分为窗口，逐窗预测并加权求和（公式 (4)），实现零样本泛化至长序列；
    - **持续学习（Continued Training）**：新增少量 co-execution 样本（如 *k=20~100*）即可 fine-tune 模型适配新模型/批大小。

## 6. 主要结论与发现

- 干扰本质是 **operator-pair-level 的共享内存路径争用**，而非任务级强度属性；
- 干扰具有 **方向性**（memory-bound 算子更易受干扰）、**算子特异性**（同 intensity 算子 slowdown 差异巨大）、**co-runner 依赖性**（固定 SM 下，不同 co-runner 导致 ResNet-50 latency 波动达 1.31×）；
- 硬件计数器分析证实：target 的 standalone duration 与 DRAM traffic 与 *δ* 相关性最强（|r| > 0.9），而 co-runner 计数器无显著全局相关性——**干扰由 target 的脆弱性主导，co-runner 的压力调节其程度**；
- PairSight 实现 **4.3% HP MAPE**，较 best baseline（Abacus）提升 5×，较 intensity rule 提升 4.4×；
- **窗口组合与持续学习机制**使 PairSight 在 zero-shot 下支持长序列（96 ops）与新模型（Llama），且仅需 ~100 样本即可将 Llama HP error 从 30.2% 降至 13.5%。

## 7. 优点

- **首创 operator-pair 级实证分析框架**：首次系统揭示 SM 分区下干扰的硬件根源（L2/DRAM path）与联合依赖性；
- **高精度 + 强可解释性**：基于物理意义明确的硬件计数器（DRAM bytes, stalls），预测误差低且特征贡献可追溯；
- **部署友好**：纯 CPU 推理（5.3 μs）、无需重训模型、支持在线 adaptation（few-shot）、兼容现有 profiling 工具（Nsight Compute）；
- **工程鲁棒性强**：window composition 解决长序列泛化，utilization-only 替代方案证明特征设计灵活（4.3% error 保持）。

## 8. 不足与局限

- **硬件覆盖窄**：实验仅在 A100 上完成，未验证跨架构迁移性（如消费级 GPU 或新架构 Hopper）；
- **场景覆盖有限**：未测试 MIG（Multi-Instance GPU）或时间片轮转（time-slicing）等其他共享模式；未考虑 kernel launch overhead 或 host-CPU 争用；
- **模型假设限制**：假设 operator streams “progress at comparable rates per window”（Section IV-D），在高度异步或动态控制流（如 LLM 的 speculative decoding）下可能失效；
- **依赖高质量 profiling**：Nsight Compute profiling 成本未量化，且对 kernel 内部 stall 原因的归因存在工具链噪声风险；
- **未开源代码/数据**：arXiv 版本未提供复现所需代码、profiled counter 数据集或 trained model，影响可验证性。
