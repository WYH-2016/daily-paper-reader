## 摘要
AI-RAN正推动无线接入网（RAN）处理与人工智能（AI）工作负载在支持GPU的计算平台上的融合，涵盖从GPU加速基站到云原生基础设施的各类场景。尽管GPU加速提升了虚拟化RAN功能的执行效率，但对时延敏感的基带处理所消耗的算力会随业务负载动态变化，从而产生瞬态空闲GPU容量，可供同部署的AI应用回收利用。现有GPU共享机制依赖粗粒度硬件分区或静态资源分配，难以在保障严格时序约束的前提下，适应以RAN时隙为单位的工作负载波动。本文提出ScaleRAN——一种面向AI-RAN的节点级弹性GPU资源管理运行时。ScaleRAN利用NVIDIA Green Contexts技术，通过一组预创建的GPU分区阶梯式地动态划分流式多处理器（SM），实现以RAN时隙为粒度的低开销资源重分配。所提出的运行时天然支持开放无线接入网（O-RAN）O-Cloud部署，这是AI-RAN的一种典型部署场景。为驱动此类资源重分配，我们设计了一种受Kubernetes自动扩缩容启发的响应式控制器，以及一种基于分位数回归与共形预测的前摄式控制器。此外，我们还开发了LDPCSim——一个基于NVIDIA Aerial构建的GPU加速工作负载生成器，以支持可复现的评估。实验结果表明，预测式细粒度GPU分区可在满足RAN时隙级截止时间的前提下，提升同部署AI工作负载可获得的GPU资源量，验证了弹性GPU共享在未来AI-RAN平台中的实用性。

## Abstract
AI-RAN is driving the convergence of radio access network (RAN) processing and artificial intelligence (AI) workloads on GPU-enabled computing platforms, ranging from GPU-accelerated base stations to cloud-native infrastructures. While GPU acceleration improves the efficiency of virtualized RAN functions, the computational demand of latency-critical baseband processing varies with traffic load, creating transient spare GPU capacity that can be reclaimed by co-located AI applications. Existing GPU-sharing mechanisms rely on coarse-grained hardware partitioning or static resource allocation, limiting their ability to adapt to slot-level workload fluctuations while preserving strict timing requirements.   This paper presents ScaleRAN, a node-local runtime for elastic GPU resource management in AI-RAN. ScaleRAN leverages NVIDIA Green Contexts to dynamically partition Streaming Multiprocessors (SMs) between RAN and AI workloads through a ladder of pre-created GPU partitions, enabling low-overhead resource reallocation at RAN slot granularity. The proposed runtime naturally supports Open-RAN (O-RAN) O-Cloud deployments, one representative AI-RAN deployment scenario. To drive these reallocations, we propose a reactive controller inspired by Kubernetes autoscaling and a proactive controller based on quantile regression and conformal prediction. We also develop LDPCSim, a GPU-accelerated workload generator built on NVIDIA Aerial for reproducible evaluation. Results show that predictive fine-grained GPU partitioning satisfies slot-level RAN deadlines while increasing the GPU resources available to co-located AI workloads, demonstrating the practicality of elastic GPU sharing for future AI-RAN platforms.

## 1. 核心问题与整体含义（研究动机和背景）

- **根本挑战**：在 AI-RAN（AI-native Radio Access Network）架构中，时延敏感的 RAN 基带处理（如 5G NR LDPC 解码）与 AI 推理/训练任务需共享同一 GPU 资源；但 RAN 负载随用户数、MCS、PRB 分配等动态变化，导致**毫秒级（slot-level，典型为 0.5 ms）GPU 算力需求剧烈波动**，产生瞬态空闲资源。
- **现有方案失效**：传统 GPU 共享机制（如 MIG 硬件分区、MPS 软共享）粒度粗（实例级）、静态或低频调整，无法在保障 RAN 严格截止期（deadline）前提下，实时释放/回收 SM（Streaming Multiprocessor）资源供 AI 使用。
- **产业驱动力**：O-RAN WG6 正推动“O-Cloud Enhancements for AI Applications”，亟需支持异构 RAN+AI 工作负载的**节点级弹性加速器运行时**；GPU 成为 5G/6G 基站与边缘云共用的核心加速平台，高效复用是经济性与可行性关键。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：构建一个**轻量、低开销、slot 粒度响应**的节点本地 GPU 运行时（ScaleRAN），实现 RAN 与 AI 间 SM 资源的**弹性、可预测、隔离式动态再分配**。
  
- **关键技术**：
  - ✅ **Green Contexts（GC）驱动的 SM 级弹性分区**：预创建一组离散的 GC 分区配置阶梯 `Π = {π₀, π₁, ..., πₚₘₐₓ}`，每个 `πₚ = (Sᴿᴬᴺₚ, Sᴬᴵₚ)` 定义 RAN/AI 各自独占的 SM 数量（如 `{4,8,...,44}` SM），所有分区在初始化时一次性创建，切换仅需重定向 CUDA Stream，**零设备重配置、无内核抢占中断**。
  - ✅ **双模控制器**：
    - **反应式（Reactive）**：受 Kubernetes HPA 启发，基于上一时隙实测 LDPC 解码延迟 `dₜ₋₁`，按比例缩放 RAN SM 配置：  
      `Ŝᴿᴬᴺₜ = Sᴿᴬᴺₚₜ₋₁ × (dₜ₋₁ / D)`，再映射到最小满足 `Sᴿᴬᴺₚ ≥ Ŝᴿᴬᴺₜ` 的阶梯档位；**上扩立即执行，下扩设 H-slot 稳定窗口防抖**。
    - **前摄式（Proactive）**：使用 LightGBM 分位数回归模型 `g_τ(xₜ, p)` 预测下一 slot 在配置 `p` 下的 LDPC 解码延迟 `τ`-分位数（如 P95/P99），再通过**单边共形预测（split conformal prediction）** 校准，得到带统计保证的上界 `Uₜ(p) = ĝ_τ(p) + q_α`；最终选择满足 `Uₜ(p) ≤ D` 的最小 `p`。
  - ✅ **协同式库集成（ScaleRAN lib）**：应用仅需包裹 CUDA kernel launch（如 PyTorch/TensorRT 模型推理循环），由库自动同步流、切换 GC 上下文，**无需重构应用、不依赖 CUDA API 拦截**。

## 6. 主要结论与发现

- **核心结论**：ScaleRAN 首次实现了**slot 粒度、低开销、统计安全的 GPU 弹性共享**，在严苛 RAN 截止期约束下，显著提升 AI 可用 GPU 资源。
- **关键发现**：
  - Proactive（Conformal P99）达成 **99.96% deadline success**，接近理论极限（100%），而 K8S-React 仅 ~98.2%；
  - 相比反应式，前摄式将 **mean SM regret 降低 45%**（8.69 → 4.80），即 AI 平均可多获约 **3.2× GPU 资源**（因 RAN 更精准“按需索取”）；
  - **AI-RAN 干扰本质是“时空耦合”**：不仅取决于 AI 推理总时长，更取决于其 kernel 是否长期独占 SM（SM footprint）及是否跨越 slot 边界（Fig.10）；
  - 共形校准有效修复分位数预测的覆盖偏差，使 empirical coverage 紧密贴合 target（Fig.8）；
  - ScaleRAN 天然契合 O-RAN O-Cloud 架构，作为 node-local service，通过标准 O1/O2 接口被 SMO 管理。

## 7. 优点（亮点）

- ✅ **创新性架构**：首个将 NVIDIA Green Contexts 用于 AI-RAN 弹性资源管理的 runtime，填补 slot-level GPU 调度空白；

## 8. 不足与局限

- ❌ **场景覆盖有限**：仅验证单 O-DU（cuPHY）+ 单 AI 任务；未涵盖 O-CU/O-RU 协同、多 RAN 功能链（MAC+PHY）、多租户 AI 任务竞争、GPU 显存/带宽联合调度；
- ❌ **硬件依赖性强**：完全基于 NVIDIA GPU 与 Green Contexts（专有技术），**不适用于 AMD/Intel GPU 或非 CUDA 生态**；
- ❌ **预测模型泛化性待验证**：LightGBM 在训练集（wide radio configs）上表现好，但未报告跨基站、跨 numerology（μ=0/2/3）、跨 LDPC base graph（BG1/BG2）的 zero-shot 泛化能力；
- ❌ **实时性边界模糊**：虽称“slot-level”，但 profile 切换仅发生在 kernel launch boundary，若 AI kernel 超长（>0.5ms），仍会阻塞 RAN 调度（Fig.10 中宽 MLP 问题），**未提出 kernel slicing 或抢占式调度等补救机制**；
- ❌ **缺乏长期稳定性验证**：实验为 10k slots（~5s real-time），未测试数小时/数天连续运行下的 controller 漂移、模型退化、内存泄漏等问题。
