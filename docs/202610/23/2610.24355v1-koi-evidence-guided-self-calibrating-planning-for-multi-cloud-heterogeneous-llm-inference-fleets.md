## 摘要
部署大语言模型（LLM）需在跨云平台、跨地域及跨市场的约140个变量中，选择合适的加速器、并行化策略、推理引擎配置及副本数量。这些决策相互耦合，且随着任务在动态变化的工作负载下竞争共享资源，最优的集群级部署方案亦持续演进。本文提出Koi——一种面向异构、多云LLM推理集群的自校准规划器。Koi采用递归式语言模型（RLM）层级结构提出假设并推理部署方案，同时由确定性组件预测服务行为、评估候选方案并控制资源放置。它将推理行为建模为一个固定的因果图，该图连接决策变量（如加速器类型、并行度）、运行时中介因子（如KV缓存压力、通信开销）以及最终结果（如延迟、吞吐量）。每次部署均强化或弱化特定范围内的因果关系，从而逐步构建一套全面的推理操作手册，供规划器指导后续决策。任务级配置被组合为集群级部署方案，并依据服务目标、资源约束、SLO风险及成本进行综合评估。在各类基准测试中，Koi相较最强基线方法提升了1.18倍的有效吞吐量（goodput），并在真实异构集群中将每Token成本降低了20%。消融实验分离了Koi架构各部分的贡献：纯语言模型得分为35.3，加入Koi确定性工具后的同一模型得分为51.6，而完整Koi规划器得分为70.8。

## Abstract
Deploying a large language model (LLM) requires choosing the right accelerator, parallelization strategy, engine configuration, and replica count amongst ~140 other variables across clouds, regions, and markets. These decisions are intertwined, and the best cluster-wide plan continually changes as jobs contend for shared capacity on shifting workloads. We present Koi, a self-calibrating cluster planner for heterogeneous, multi-cloud fleets. Koi uses a Recursive Language Model (RLM) hierarchy to propose hypotheses and reason over deployment while deterministic components predict serving behavior, score candidates, and control placement. It represents inference behavior as a fixed causal graph linking decisions (e.g., accelerator, parallelism), runtime mediators (e.g., KV-cache pressure, communication overhead), and outcomes (e.g., latency, throughput). Each deployment strengthens or weakens scoped causal relationships, building a comprehensive playbook for inference that the planner employs to guide future decisions. Job-wise configurations are composed into cluster-wide plans and evaluated against serving objectives, resource constraints, SLO risks, and cost. Across benchmarks, Koi achieves 1.18x greater goodput than the strongest baseline while reducing $/token by 20% in a real heterogeneous cluster. Ablations isolate the contribution of Koi's architecture: a pure language model attains a composite score of 35.3, the same model equipped with Koi's deterministic tools reaches 51.6, and the full Koi planner reaches 70.8.

- **现有方法失效原因**：
  - 单任务优化器（如AIConfigurator、Prism）忽略跨任务资源机会成本，易导致“先到先得”式次优分配；

## 2. 方法论：核心思想与关键技术细节

- **总体范式**：**证据引导（Evidence-Guided） + 自校准（Self-Calibrating） + 分层代理（Agentic）** 的闭环控制架构，解耦“假设生成”与“确定性验证”。

- **核心组件与流程**：
  - **固定因果图建模（Causal DAG）**：  
    构建静态有向无环图 $X \to V \to Y$，其中  
    - $X$：可控决策变量（加速器、TP/PP、量化、batching等）；  
    - $V$：可观测运行时中介量（KV缓存压力、pipeline bubbles、通信延迟、SM利用率、HBM带宽占用等）；  
    - $Y$：服务结果（p99 TTFT、p99 TPOT、吞吐量、$/token、SLO满足率）。  
    所有边 $e \in E$ 维护Beta分布信念 $p_e \sim \text{Beta}(\alpha_e, \beta_e)$，其置信 $c_e = \alpha_e / (\alpha_e + \beta_e)$ 与不确定性 $U(\alpha_e,\beta_e)$ 随部署证据动态更新。

  - **机制（Mechanism）与假设生成**：  
    语言模型（RLM层级）基于当前快照、job profile、scope匹配的机制，提出可检验的因果假设（如“对Llama-70B+H100，提升PP会因stage imbalance降低吞吐”），仅当路径 $X \to V \to Y$ 在注册图中存在且scope匹配时才被采纳。

  - **确定性代理（Deterministic Surrogate）**：  
    基于AIConfigurator扩展的算子级延迟模型 + replay simulator，预测各候选ladder的$y_i(L_i)$；引入**CUSUM残差检测器**判断预测偏差是否显著（$S^+_k > h$ 或 $S^-_k < -h$），将每次部署同时视为**服务执行**与**机制验证实验**。

  - **联合规划与评分函数**：  
    每5分钟tick执行8阶段闭环（快照→采集→比对→更新→提案→评估→提交→闭环）。集群计划$P_t = \{L_i\}$得分定义为：  
    $$
    \Phi(P) = \sum_{(i,L_i)\in P} \left[ J_i(L_i) - \gamma p^{\text{brk}}_i(L_i) - \lambda_t \text{Switch}_i(L^{(t-1)}_i, L_i) \right] + \beta_t \text{Expl}(P)
    $$  
    其中：  
    - $J_i$：加权Tchebycheff标量化目标（兼顾Pareto前沿与权重）；  
    - $p^{\text{brk}}_i$：基于历史残差带（quantile + Wasserstein半径$\epsilon$）估计的SLO违约概率；  
    - $\text{Switch}_i$：冷启动、并行执行、终止、风险四维重配置成本；  
    - $\text{Expl}(P)$：鼓励测试高不确定性边/机制的探索项；  
    - $\beta_t, \lambda_t, \epsilon_t$ 等参数由慢循环（slow loop）基于Q1率（预测≈观测）等信号自适应调节。

  - **分层代理架构**：  
    Root Planner分配预算书（budget book）限定各job可选硬件池 → Specialist Sub-Agent（per-job）执行反向DAG查询（给定SLO目标，追溯影响它的$X$决策）→ 提出少量候选ladder → 确定性模块验证物理可行性、预测、评分 → Joint Selector在容量约束下全局优化$\Phi(P)$。

- Koi在**真实104-GPU异构集群**上达成：

## 7. 优点

- **范式创新**：首次将**因果推理（Causal DAG）**、**自我校准（Slow Loop）** 与**分层代理（RLM+Deterministic）** 深度融合，解决LLM推理规划的可信赖性与适应性矛盾。
- **工程务实**：RLM仅用于**提案**（proposal），所有**验证、评分、约束检查、执行均由确定性代码完成**，杜绝LLM幻觉影响生产；“沙盒化LLM”设计保障安全性。
- **证据驱动**：每个部署既是服务也是实验，利用可观测中介量$V$归因性能瓶颈（如区分KV压力vs. pipeline bubbles），指导精准干预。
- **可扩展性强**：新增决策轴（如prefill-decode disaggregation、新加速器AMD/TPU）只需接入对应$V$指标，无需重构核心逻辑；算力开销与决策空间维度无关，仅取决于候选数。
- **评估严谨**：采用几何平均三支柱指标，拒绝单一维度优化；所有基线在完全相同条件下对比，排除环境偏差。

## 8. 不足与局限

- **实验覆盖局限**：
  - 未测试**超大规模集群（>1000 GPU）** 或**极端长尾SLO（如TTFT<10ms）** 场景；
  - 批处理任务仅覆盖固定deadline，未涉及**动态deadline调整**或**优先级抢占式批处理**。
- **潜在偏差风险**：
  - 仿真器LLMServingSim 2.0虽经增强，但对**前沿引擎（如vLLM 0.6+、TensorRT-LLM新特性）** 的建模保真度存疑；
  - CUSUM检测依赖残差分布假设，对**突发性、非平稳噪声**（如网络抖动、硬件降频）鲁棒性需进一步验证。
- **应用限制**：
  - 依赖**细粒度运行时中介量（$V$）上报能力**，若底层引擎不暴露KV压力、pipeline bubbles等指标，则因果图部分失效；
  - 当前聚焦**推理服务**，未扩展至**训练/微调/RLHF**等生命周期其他阶段（尽管论文讨论了可扩展性）；
  - RLM提示工程与机制scope定义依赖专家知识，自动化scope发现仍是开放问题。
