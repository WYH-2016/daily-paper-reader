## 摘要
当前面向异构环境的大模型训练系统通过在流水线各阶段分配不等数量的网络层来实现负载均衡，其目标是通过唯一的流水线配置使各阶段执行时间趋于一致。然而，该方法未能解决关键的内存约束问题，且其负载均衡粒度本质上过于粗糙。本文提出异构流水线并行（Heterogeneous Pipeline Parallelism, HPP），一种支持在异构流水线间进行高效、细粒度数据均衡的新方法。为应对HPP面临的核心挑战——最优配置搜索开销过大以及非对称All-Reduce带来的高通信开销，我们设计了ETH训练系统。ETH采用分层负载均衡框架，在异构流水线之间及单个流水线阶段内部联合优化负载分配。为缓解非对称通信开销，ETH实现了分块式梯度聚合；同时，它集成了专门优化技术，显著降低了HPP配置搜索开销。实验评估表明，相较于当前最先进的系统，ETH最高可实现2倍的训练加速，并将配置生成开销降低至原来的1/56。代码开源地址为：https://github.com/YuMJie/ETH。

## Abstract
Current heterogeneity-aware training systems for large models balance workloads by assigning unequal numbers of layers across pipeline stages, a strategy aimed at equalizing execution time through a unique pipeline configuration. However, this approach fails to address critical memory constraints and suffers from inherently coarse balancing granularity. In this paper, we propose Heterogeneous Pipeline Parallelism (HPP), a novel approach enabling efficient and fine-grained data balance across heterogeneous pipelines. To address HPP's key challenges, prohibitive search overhead for optimal configurations and high communication overhead from asymmetric All-Reduce, we design the ETH training system. ETH employs a hierarchical workload balance framework that jointly optimizes balance across heterogeneous pipelines and within individual pipeline stages. To mitigate asymmetric communication costs, ETH implements block-wise gradient aggregation. Furthermore, it integrates specialized optimizations that dramatically reduce HPP configuration search overhead. Evaluations demonstrate ETH achieves up to 2x training speedup while reducing configuration generation overhead by up to 56x compared to state-of-the-art systems. The code is available at https://github.com/YuMJie/ETH.

## 1. 核心问题与整体含义（研究动机和背景）

- **根本矛盾**：当前异构训练系统（如 Metis、HexiScale）依赖“层分配均衡”（layer balancing）——即给计算能力强的设备分配更多网络层，以拉平各流水线阶段执行时间。但该策略存在两大结构性缺陷：
  - **内存瓶颈不可忽视**：层越多 → 参数/梯度/优化器状态显存占用越高 → 显存受限设备被迫降配或触发重计算（recomputation），反而加剧负载不均；论文指出近5年算力增长16×而显存仅增<5×，导致Ascend 910B2/B3等设备最高32%算力闲置。
  - **粒度过于粗糙**：GPT-3-13B仅64层，8路PP下每阶段仅约5层；增减1层即改变单设备负载20%，导致额外16%流水线气泡（pipeline bubbles）。
- **关键洞察**：大模型训练普遍采用超大全局批大小（GBS），而**数据维度天然支持细粒度切分**。论文发现，在Ascend 910B2/B4异构集群上，当内存-算力失配率从1.0升至1.9时，层平衡的延迟比（max/min）从1.11恶化至1.87，而数据平衡稳定在1.09–1.17；且DeepSeek系列模型GBS达层数的48–251×，为数据均衡提供充足调度空间。

## 2. 方法论：核心思想与关键技术细节

- **核心范式**：提出**数据均衡异构流水线并行（HPP）**——允许多个独立、异构的流水线并行运行，每个流水线配置**不同本地批大小（LBS）** 和**微批大小（MBS）**，通过调节数据量而非层数实现跨流水线负载均衡；同时允许各流水线内部各阶段采用差异化TP/DP/层分配/重计算策略。
  
- **ETH系统三大支柱**：
  - **分层负载均衡框架（Hierarchical Workload Balance）**：
    - *阶段级优化*：对每个流水线，固定其LBS后，求解最优TP/DP度、层分配、MBS及重计算操作，目标是最小化首微批总耗时 + 最慢阶段耗时 × 剩余微批数（公式1）。
    - *跨流水线LBS分配*：在满足∑LBS ≥ GBS且LBS_i ≡ 0 (mod MBS_i)约束下，贪心分配LBS_i使所有流水线最大完成时间最小（公式2–5）。
    - *阶段配置精调*：用新分配的LBS_i替代原公式1中的GBS，重新优化各流水线内部配置。
  - **块级梯度聚合（Block-wise All-Reduce）**：
    - *问题*：HPP中DP组内设备因TP度不同，梯度地址与尺寸不一致（图5），传统device-wise（填充开销大）或tensor-wise（连接数爆炸）均低效。
    - *方案*：① **Partition**：所有设备按层划分梯度；TP度低于组内最大值（tp_max）者，进一步沿算子/TP分片维度切分；② **Combine**：低TP设备将细粒度块对齐至tp_max设备的块结构；③ **Fusion**：合并同一DP组覆盖的相邻层块，减少All-Reduce次数（图7）。
  - **HPP配置快速搜索（Minimal Overhead Search）**：
    - *Pipeline Caching*：缓存已优化过的子流水线（如⟨V,V⟩）配置，避免重复计算。
    - *Early Skipping*：对候选流水线组，用确定性（二分图匹配）+ 近似（基于缓存流水线吞吐缩放）方法估算上界吞吐，若总上界低于当前最优则跳过。
    - *Search Ordering*：按计算方差代价函数 `Cost = V_inter/Gbs + V_intra/L`（公式9）排序，优先搜索计算能力更均衡的组合。
    - *Dynamic Programming*：对大规模集群（n设备），按流水线数p递增顺序DP搜索：`T_p(R_n^p) = max_i [T_{p−1}(R_i^{p−1}) + T_1(pipe_{i+1}^n)]`（公式10），将复杂度从指数级降至O(n³)。
